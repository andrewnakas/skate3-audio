# sub_82B460A0

Non-leaf, 286 lifted lines, 76,462 calls per boot on `RwAudioCore Dac`. Census gate-1 pass, closure
of 6, nothing outside it but `82F4DED0`/`82F4DFB0` (sin/cos, reached through sub_82B45788). Only
caller is sub_82B29BE0 (twice), which resets r3 before its next call: mask `kReturnNone`.

Arguments: r3 = the listener/format config object, r4 = the 16-byte panner entries sub_82B45C50
writes, r5 = source count, **r10 = the matrix base** (`mr r27,r10`, not a positional argument --
sub_82B29BE0's port sets r10 by hand for exactly this reason), f1/f2/f3/f4 = four scalars held in
f31/f29/f28/f30 across the call.

Object fields used: `+56` s32 destination channel count (compared with 2 and 6, and `== 6` picks
column 5 over column 7), `+172/+176/+180/+184` the four gain indices the callees store by. The
callees additionally read the speaker table at `+0..+55` and the thresholds at `+60..+168`.

Two paths, chosen by `+56 == 2` read at entry:

- **stereo**: no callees. For each of r5 sources, read entry y (`entries + 16i + 4`), form
  `right = 0.5*(y+1)`, `left = 1-right`, divide 1.0 by `sqrt(left^2 + right^2)`, scale by f1 then
  f4, and store `total*right` at `matrix + 32i` and `left*total` at `matrix + 32i + 4`. A zero or
  negative r5 writes nothing.
- **anything else**: `rows = r5` when r5 < 6, else `r5 - 1`. For each row: sub_82B454B8, then
  sub_82B45788, then sub_82B45B60, all with r3 = object, r6 = the row, r4 = the entry, f1 = f2
  (f29) for the first two and f1/f2/f3 = f1, f4, `entry+8` for the third. Then `+56` is **reloaded**;
  if it is >= 6, `column = 5` when it reads exactly 6 else 7, and: r5 == 6 or r5 == 8 selects
  `row = 5` or `row = 7`, zeroes that whole row and that whole column (8 `stfsu` each, from
  `matrix + 4*column - 32` and `matrix + 32*row - 4`), then writes f3 into their crossing cell; any
  other r5 fills that column with f3 and clears nothing.

The original reloads only r4 between the first two calls, relying on sub_82B454B8 leaving r3 and r6
alone. The port sets r3, r4 and r6 explicitly before each call -- same values, and it does not
depend on a volatile register surviving a call that may itself be promoted. r5 is deliberately left
as the callees leave it: none of the three reads r5.

The `stwu r1,-176(r1)` **is** reproduced: sub_82B454B8 spills f30/f31/r31 into the red zone and the
sin/cos helpers under sub_82B45788 spill at r1-8..r1-32, all below the caller's r1.

Stores: the two per row on the stereo path; through the callees at most `[row, row+28)` plus
`row + 4*index` for the four indices; then 16 zero words and one cell, or 8 words of one column.
Window: `[matrix, matrix + 32*(r5-1) + 8)` on the stereo path, else the whole 256-byte matrix as one
span -- a superset, since unwritten bytes compare equal. Returns false when r5 (or `rows`) exceeds 8
rows, when any of the four index words is >= 8 (a callee would store outside the 32-byte row), or
when the matrix overlaps `+172..+187` (the indices are reloaded inside the callees after their own
stores, so a store landing there makes a later address unknowable). Reads recorded: `[object, +192)`,
the entries, and six rodata singles.

Gates: 1 pass (no import, no indirect call, no lock, no allocation anywhere in the closure), 2 pass
except the guards above, 3 pass (no timebase), 4 pass (all output is stores). STATUS: **verified** -- the .inc header carries the status and the call count the harness session recorded; this note was written before that session ran.

Unsure of:
- The rodata values are quoted from the sub_82B453D8/sub_82B454B8 notes (0.5f `0x8209975C`, 1.0f
  `0x8231A844`, 0.0f `0x82165A10`); `probe/harness/out/image` is **empty on this tree**, so they were
  not re-read. Nothing depends on them: the body loads through the guest map.
- Reading `+56` as a channel count and column 5/7 as LFE/side is inference from the 5.1/7.1 compares;
  the code is faithful either way.
- The mirror of sub_82B454B8's and sub_82B45B60's window logic here is a copy, not a reference
  (`recomp/src/audio_ports/sub_82B454B8.inc` is in a different aggregator TU, sub_82B45B60.inc is in
  the same one but the copy keeps this file readable): if either callee's write set is ever found
  wider than `[row, row+28) + row + 4*index`, this window set must widen too.
- Operand order on commutative `fmuls` is kept as lifted for NaN propagation
  (docs/vmx128-exactness.md rule 4).
