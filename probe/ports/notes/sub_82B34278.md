# sub_82B34278

Lifted: `skate3_recomp.67.cpp:54313`, 1032 lines -- the largest gate-1 function in the sweep.
223,568 calls during boot on `RwAudioCore Dac`. Renders one block of a Dac stream. `r3` = the
~476-byte object, `r4` = the descriptor pair (`+28`/`+32` buffers, `+16` current time as a double).
Returns 1 normally, 0 when nothing at all was produced.

## Shape

1. `+472` and `+471` both set: `sub_82B34108(object)` is the whole call, its result returned.
2. Clear `+472`, `pair+48` and `+420`; find the current 48-byte record at
   `object + [object+464] + 48*[object+469]`. A record in state 0 or 4 ends the call; a record whose
   `+20` (total) is zero is marked state 4 and popped with `sub_82B349A8`, repeatedly. Only states 2
   and 3 render.
3. The record's `+16` (rate) must equal `[object+456]` and its `+47` (channels) must equal
   `[object+42]`, or `loc_82B34974` publishes the record's format into both, empties the block and
   returns 1 -- the caller's cue to reconfigure.
4. The consumer slot: `object + 16*[object+474]`, status byte at `+113`. Status 0 steps the cursor
   (branchlessly wrapping at 20) until it hits `[object+473]` or a non-empty slot; the slot must then
   read 1 (ready) or the call ends.
5. The start timestamp at record `+0`: equal to the pool's zero double means render now. Otherwise
   `ahead = start - [pair+16]`; if that is positive, `ahead * [[pair+40]+12]` rounded to single must
   be under the pool float at `0x822F8A48`, else the call bails (clearing `+432`). Within the bound,
   `ahead * [pair+56]` truncated by `fctidz` is a frame count: non-zero emits that many frames of
   silence (clamped to `[object+460]`), swaps the pair and returns 1; zero falls through after
   writing the pool zero back into record `+0`.
6. Render: take `([record+44] + 127) & ~127` off `[[object+8]+32]`, publish `[record+8]` at `+420`,
   ask `sub_82B23C10(stream, slot+4)` how much is left, discard `min(that, [record+28])` frames
   through `sub_82B3CA60` 256 at a time (accumulating into `skipped`), then render
   `min([object+460], available - preroll)` in one call. With frames produced, set `+471` and copy
   the LAST sample of each of `min([record+47], [object+466])` channels into the table at
   `object + [object+462]`.
7. Publish: `pair+48` = frames, swap `+28`/`+32`, `pair+60` = channels, `pair+52` = rate,
   `object+424/428/436` = the record's `+12`/`+16`/`+20`. `+432` starts at `[record+32]+[record+36]`
   when it is zero, then gains `produced + skipped`, and the slot's own `+108` counter gains the
   same. When `+432` reaches the record's total: a non-negative `[record+24]` becomes the new `+432`
   (a loop), a negative one retires the record (state 4, scratch handed back, `sub_82B349A8`, and the
   next record's scratch taken if it has a stream).
8. `loc_82B3489C`: while nothing is left for the slot, retire it (status 2), step the cursor, and ask
   `sub_82B23C10` about the next slot -- looping until one has frames or is not ready.
9. `+420` is cleared and the scratch pointer restored; `pair+60` and `pair+52` get the object's own
   published channel count and rate. Return 0 only when nothing was rendered, nothing was discarded
   and `[object+460]` is non-zero.

## Gate verdict

**gate-1 at depth 1.** `sub_82B3CA60` -- called once per pre-roll chunk and once per block -- runs the
stream's fill function through the pointer at its `+20` (`bctrl` at 0x82B3CB80 and 0x82B3CCA0) and
`sub_82B3C9D8` under it makes four more. A replay would run a decoder twice over the same source.
The other callees are benign: `sub_82B23C10` and `sub_82B349A8` are verified ports, `sub_82EE5E80`
is memset, and `sub_82B34108` is outside the corpus but only reached on the pass-through path.
`Windows()` returns false.

Gate 2 would also fail. The write set depends on `sub_82B23C10`'s return value (how many frames are
available, which selects between the pre-roll, render and slot-retire paths), on
`sub_82B3CA60`'s return (how many were delivered, which sizes the tail-sample copy), and the
slot-retire loop walks the ring an unpredictable number of times. The census marks 16 stores
`gate2_suspect`.

## Uncertainties

- On the "too far ahead" path `lwz r26,80(r1)` reads the `fctidz` spill slot **before anything has
  written it**, so the frame count comes from whatever the stack held. The value is dead -- the flag
  register is 0 on that path and the next test bails -- but the load is reproduced as a load.
- The tail-sample copy is written as one loop. The original is an unrolled-by-four loop of
  `((lanes-4)>>2)+1` iterations plus a remainder loop, and the two together cover channel 0 through
  `lanes-1` exactly once each in order, with the descriptor's stride and data pointer reloaded per
  sample. Checked at lanes = 4, 5, 6, 7, 8 and below 4. The remainder loop clobbers r6 (the channel
  count); `loc_82B34784` recomputes r6 as `available - produced - skipped` before anything reads it,
  which is what the `loc_82B34894` test actually looks at.
- Three `addi` results are dead and not reproduced: `addi r10,r11,108` at `loc_82B34784` (the load
  overwrites r10 immediately) and the two spare record addresses the scheduler materialised.
- `rlwinm r10,r11,4,20,27` in the retire loop masks `16*cursor` to `0xFF0`, which drops nothing for a
  cursor under 20. Kept as written with the mask spelled out.
- `object+424`, `+428` and `+436` are only known as "the record's `+12`, `+16` and `+20`, published".
  The `+16` reading as a rate is solid (it is also `pair+52` and the format-change test); the other
  two are not established.
- The 16-byte slots: only `+0` (u32 count), `+4` (u8 stream index for `sub_82B23C10`) and `+5` (u8
  status) are touched here, addressed as `object + 16*i + {108, 112, 113}`, which is how they are
  spelled in this port. 20 slots at that base end at `object+418`, just below `+420`.
- Whether the retire loop can spin is not established. It re-reads the cursor each pass and steps it
  every time, so it terminates within 20 iterations unless `sub_82B23C10` keeps reporting frames for
  successive ready slots -- in which case it is doing real work.
