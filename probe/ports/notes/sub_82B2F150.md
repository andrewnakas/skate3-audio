# sub_82B2F150

Arguments: `r3` = the object (r27). No other entry register is read. Returns 1 in `r3` on
success, 0 the moment a `sub_82B3D668` request fails. Lifted at skate3_recomp.67.cpp:42292,

What it does: acquires or re-acquires this object's mix slots in two sets.

- Primary set, always, six entries (`cmpwi cr6,r28,6`): index table at `+388` (u32, stride 4),
  four gains at `+504` (singles, stride 36), slot at `+720` (stride 60). The gains are written
  unconditionally every iteration: `-(single at index_at+48)` to `gains-4`, `-(single at
  index_at+72)` to `gains+0`, the first negation again to `gains+4`, and the pool constant at
  `0x822F896C` to `gains+8`. Then `slot+20` is compared, signed 32-bit, against `index+1`; equal
  means the slot is already current and the iteration ends there.
- Secondary set, once per object, latched by the byte at `+1088` (nonzero on entry skips the
  whole set and returns 1) and counted by the byte at `+1089`, reloaded at the foot of the loop.
  Gains at `+92` (two singles, stride 24), slots at `+164` (stride 60), and `r30` walking `+1068`
  by 4 so its two reads land on the tables at `+1060` (a single) and `+1072` (the index). The
  shared single at `+1084` is reloaded every iteration. No negation and no skip test here.
  On success the latch at `+1088` is set to 1; a count of 0 still sets it.

`sub_82B3D668` takes the request block at `slot-20` in r3 and `index + bias` in r4, bias 3 for
the primary set and 2 for the secondary. Its return is tested as `r3 & 0xFF`.

Stores:
- `gains-4`, `gains+0`, `gains+4`, `gains+8` -- 4 bytes each, primary, every iteration
  (`object + 500/504/508/512 + 36*i`, i in 0..5)
- `slot+16` u32, `slot+20` u32, `slot+36` u8, `slot+12` u32, `slot+32` u32 -- primary republish,
  in that order (`object + 720 + 60*i`)
- `gains-4`, `gains+0` -- 4 bytes each, secondary (`object + 88/92 + 24*i`)
- `slot+16` u32, `slot+36` u8, `slot+20` u32, `slot+32` u32, `slot+12` u32 -- secondary
  republish, a DIFFERENT order from the primary one (`object + 164 + 60*i`)
- `object+1088` u8 = 1 -- the latch
- the frame: the r26-r31 spills at entry_sp-56..-16, the link word at entry_sp-8, the f31
  doubleword at entry_sp-64, and the back chain at entry_sp-144. All inside the 144 bytes this
  call allocates, so none is a window.

Window rationale: the write set IS enumerable from entry state -- six primary slots plus at most
255 secondary ones, from the byte at `+1089`. It fails the span budget long before it fails
enumerability: six primary iterations alone need 6*(4 gain spans + 5 slot spans) even after
coalescing the adjacent gains, and the secondary loop is unbounded in practice at 255 entries.
`Windows()` returns false, but the gate label is gate 1, not gate 2 -- gate 1 is reached first
and is the honest reason.

Gate verdict: **gate 1**. `sub_82B3D668` (skate3_recomp.68.cpp:10232) loads a global from
`r20 + 30252`, takes that object's `+36` allocator, reads its vtable and calls slot `+4` with
`r7 = 128` through `bctrl` at `0x82B3D6F8`. That is an allocation, so the shadow harness can
never replay this function: the rewind would return the block twice and the second run's
addresses would differ from the first's. The census agrees (`gate1: fail, reason indirect, at
sub_82B3D668, depth 1`); the closure also reaches `82B3D590`, `82EDF460`, `82EE7460`, `82F52FB8`.

Result mask: the declared mask is `kReturnR3`, which is honest -- the caller reads the 0/1 byte.
Lint check 5 would reject `kReturnNone` on a gate-labelled port that declares no writes, and
`kReturnR3` is what the function actually returns, so there is nothing to reconcile here.
