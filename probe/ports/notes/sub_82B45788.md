# sub_82B45788

Non-leaf, 608 lifted lines, 77,736 calls per boot on `RwAudioCore Dac`. Census gate-1 pass, closure of
3: `82F4DE80` (a leaf with **no stores at all**), `82F4DED0` and `82F4DFB0` (the sine and cosine
helpers named in the note for sub_82B29BE0; each writes only its own red zone at r1-8..r1-32). No
import, indirect call, lock or allocation anywhere in the closure. Callers: sub_82B45440 and
sub_82B460A0, both of which reset r3/r4/r6/f1 before their next call, so the mask is `kReturnNone` and
the gain stores carry the comparison.

Arguments: r3 = the same config object sub_82B454B8 / sub_82B45B60 / sub_82B460A0 take, r4 = the
source record (`+8` squared length, `+12` angle), r6 = the f32 gain array, f1 = a weight used only in
sector 1.

Object fields: `+56` s32 count (compared with 6 and 8), `+60/+64/+68` three f32 sector bounds,
`+72` the centre scale, six coefficient blocks of four singles at `+76`, `+92`, `+108`, `+124`,
`+140`, `+156`, and `+172/+176/+180/+184` the four gain indices (used as `4*index`, the same fields
sub_82B454B8 and sub_82B45B60 read).

Shape: `angle = (record+12 + obj+60) * K1` with K1 the single at `0x822F8904`; `82F4DE80(angle)` is
rounded to single and subtracted from `angle`, and the remainder times K2 (`0x820B411C`) minus
`obj+60` is the reduced angle. Sine and cosine of that come from the two helpers, each `frsp`'d. Then
a seven-way ladder, in this order:

| test | coefficients | destinations |
|---|---|---|
| reduced < `+60` | `+76` (+ `+72`) | `4*idx176`, `4*idx172`, and `gains+4` when count >= 6 |
| reduced < `+64` | `+92` | `4*idx172`, `4*idx180` |
| reduced < `+68` and count == 8 | `+108` | `gains+12`, `gains+20` |
| reduced < K2 - `+68` and count == 8 | `+124` | `gains+20`, `gains+24` |
| reduced < K2 - `+64` and count <= 6 | `+124` | `4*idx180`, `4*idx184` |
| reduced < K2 - `+64` and count == 8 | `+140` | `gains+24`, `gains+16` |
| otherwise | `+156` | `4*idx184`, `4*idx176` |

Each sector projects `(sin, cos)` through its four coefficients into two values, divides `record+8` by
`sqrt(p^2 + s^2)`, and **mix-adds** `p*norm` and `s*norm` into its two gain slots. Sector 1 is the
exception: it splits a share of `min(left, right) * f1` out into the centre channel (scaled by `+72`),
subtracts it from both, and normalises over three terms rather than two -- with the centre term
exactly `0.0f` when the count is below 6.

Two structural details the port keeps and a reader might "simplify" away:

- In the three index-pair sectors (2, 5, 7) the SECOND index is read from the object **after** the
  first store (loc_82B45B3C). In the three fixed-slot sectors (3, 4, 6) both old gains are loaded
  before either store. So loc_82B45B3C is inlined at each of its three arrival points.
- Arriving at loc_82B45A80 from the `bge` above it re-tests the same f0, so that arm always falls
  through to sector 7; sector 6 is reachable only through the `count > 6` branch. The port writes that
  as `inside && count == 8` after `inside && count <= 6`, which is the same set of paths.

`stwu r1,-160(r1)` **is** reproduced: the sine and cosine helpers spill below the caller's r1.
`fmr f27,f31` is not: f27 is written there and never read, and `__restfpr_27` puts the entry value
back.

Windows: which sector runs cannot be predicted from entry state without redoing the reduction and both
trigonometric calls, so the union of all seven is declared -- one 28-byte span over `[gains, +28)`
(covering the fixed slots +4/+12/+16/+20/+24 and any index below 7) plus a 4-byte span per index whose
`4*index` falls outside it. At most 5 spans, 44 bytes. Returns false when any declared span overlaps
`+172..+187`, for the reason above: sectors 2, 5 and 7 re-read an index after a store, and that cannot
be supersetted. That is the same exit sub_82B454B8's port takes.

Gates: 1 pass, 2 pass except the index-aliasing case, 3 pass (no timebase), 4 pass. STATUS: **verified** -- the .inc header carries the status and the call count the harness session recorded; this note was written before that session ran.

Unsure of:
- `82F4DE80` read as a reduction (round-to-integer or similar) is inferred from the `frsp` + `fsubs`
  that follow it; the port does not depend on which function it is.
- `0x822F8904` and `0x820B411C` were NOT read: `probe/harness/out/image` is empty on this tree. K2
  doubles as the value the two reflected bounds are subtracted from, which is consistent with it being
  a full turn in whatever unit the bounds use, but that is an inference.
- Naming the coefficient blocks "sectors" and `+72` a centre scale comes from the destinations they
  feed (`gains+4` is sub_82B454B8's centre slot), not from any symbol.
- Operand order on commutative `fmuls`/`fadds` is kept as lifted for NaN propagation
  (docs/vmx128-exactness.md rule 4).
