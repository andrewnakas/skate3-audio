# sub_82B46B30

Leaf, 324 lines, `RwAudioCore Dac`, 16,314 calls in the session that verified it (18,684 in the
screening profile). r3 = the output cursor, r4 = a
descriptor: `u32[r4+4]` is a planar float buffer and `u16[r4+14]` is the floats per plane, used
only as the plane stride. Six planes at `buffer + 4*n*p`, p = 0..5. It interleaves them into
24-byte frames at r3, with a channel remap, and leaves r3 past the last frame written.

Store set: one contiguous block at r3. Per frame, six `stfs` at +0, +4, +8, +12, +16, +20,
sourced plane 0, 2, 1, 5, 3, 4 in that slot order (equivalently plane p -> slot
{0,8,4,16,20,12}[p]). The unrolled loop does four frames and `addi r3,r3,96`; the tail loop does
one frame and `stfsu` +24. Both emit the six stores in plane order 1, 2, 4, 3, 0, 5, which this
port preserves. The only other store is `std r31,-8(r1)`, the function's own red zone.

Window: `{r3, 6144}`, one span, plus six 1024-byte reads at the planes and 12 bytes of the
descriptor. The frame count is **not** variable: the limit is `addi r4,r5,1024` -- a literal
added to the cursor's own register -- so the span is always exactly 1024 bytes, 256 frames,
64 unrolled iterations consuming it exactly, and the tail loop is dead. That is what makes the
write set enumerable and why the 30 flagged `r3+k`/`r11+k` stores collapse to one span. The tail
loop is written anyway, faithfully, in case that literal ever stops being the whole story.

Gates: 1 passes (no callees, no imports, no indirect calls), 2 passes per the above, 3 passes
(no `mftb`), 4 -- `kReturnR3`, because r3 is left as the advanced cursor. If the callers treat
this as void, r3 is scratch and comparing it costs nothing: the port reproduces it exactly as
`entry_r3.s64 + 96 * iterations`, keeping the cursor 64-bit and casting only at the store, since
`addi r3,r3,96` carries into bit 32 while the store address uses the low word.

Unsure of two things. `u16[r4+14]` is read as a stride and the 1024 as a byte count, so they
agree only if the field is 256; if it is not, the planes overlap and the reads still enumerate
correctly but the "six planes" reading is wrong. And the first `cmplw`/`bge` compares the LOW
words of `start` and `start+1024`, so it early-outs only on a 32-bit wrap; reproduced, never
expected to fire, and if it ever does the call writes nothing.
