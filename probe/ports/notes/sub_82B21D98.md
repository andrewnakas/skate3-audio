# sub_82B21D98

Non-leaf, 260 lifted lines, 18684 calls on the boot session, `RwAudioCore Dac`. Census gate-1
verdict: pass, closure of 6 with only `82EE5E80` (memset) outside the corpus, read by hand for
port_82B21F58. Callees: `82B426D0` (the routing mix), `82B46B30` (the interleave), `82B20E18` (the
one-shot ramp). No imports, no indirect calls, no timebase. Mask `kReturnNone`: r3 is left holding
whatever the last callee returned, and the only caller (`sub_82B21F58`, verified) overwrites it with
`li r3,1` immediately.

Argument: r3 = the object, unchanged from sub_82B21F58's own r3.

`probe/ports/notes/sub_82B21F58.md` describes this function step by step, and this port's `Windows()`
**mirrors that file's `Windows()`** -- same spans, same two refusals, same deep-callee bounds. Those
two files must move together: a change to either write set needs a change in the other.

Sequence: eight source plane pointers into sp+80..108 (`[srcDesc+4] + 4k*u16[srcDesc+14]`,
`srcDesc = [[r3+44]+28]`, multipliers spelled out one per instruction rather than looped, which is
how the eight-entry size is known); then, if the output-count byte at `0x8306705D` is non-zero, that
many destination pointers into sp+112.. (`stwu r11,4(r10)` from sp+108, so a 64-bit running sum
truncated at each store); then `sub_82B426D0(sp+112, sp+80, outputs, 256, pairTable + 2*outputs - 2,
opTable)`; then `sub_82B46B30(block, dstDesc)` with `block = [r3+84] + ((3*[r3+92]) << 11)`; then, if
the ramp byte at `0x83067057` is set, `sub_82B20E18(block)` and `stb 0` to clear it; then clamp all
1536 words of the block in place, low bound first.

Stores outside the frame: `0x83067057` (1 byte, only on the path that read it set) and the clamp's
`stfs` into the block. Everything else this call writes is its own frame: the two pointer arrays.

Exactness details worth keeping:

- The `fcmpu` of `[r3+52]` against the constant at `0x82257308` selects between two blocks that
  compute the **same** pair-table address (`lis -32241 ; addi -10548` on both sides, only the
  register allocation differs). The branch is vestigial; cr6 is not compared. Both `lfs` are kept
  because they are reads the window builder records.
- The clamp's trip count is a constant 1536: the lifted `subf`/`addi -1`/`rlwinm 30,2,31`/`addi 1`
  runs on a difference that is always exactly 6144. The guard that actually matters is the
  **unsigned** `cmplw r31,r11` before it, which skips the whole clamp if `block + 6144` wraps 2^32.
- The clamp leaves a NaN word alone: `bge` after the low compare and `ble` after the high compare
  are both taken on an unordered result, which is what `<` and `>` do in C++ with a NaN operand.
- `3 * [r3+92]` is formed by a 64-bit `add` whose carry the following `rlwinm` discards, so the
  offset is 32-bit; `block` itself keeps its 64-bit `add` because r31 is passed on in r3 to two
  callees, and only the addressing truncates.
- The frame move **is** reproduced: sub_82B426D0 dereferences the two arrays in this frame and
  builds its own frame below them.

Window: `{block, 6144}`, `{dstBase + i*dstStride, 1024}` per output plane, and `{0x83067057, 1}`
when set -- at most 10 spans and 14337 bytes. Refuses on a null object/holder/descriptor, on an
output count above 8 (the sp+112 array holds eight, and past that the fill and memset loops walk
into frame scratch), on a block whose end wraps 2^32, and on a routing byte naming a destination
plane at or past the output count (the original would mix 1024 bytes through an uninitialised frame
word, an address this builder cannot name).

Unsure of: the same two things port_82B21F58 records -- the plane-descriptor fields beyond `+4` and
`+14` were not examined, and `[r3+52]`'s meaning is unknown because the compare it feeds is dead
either way. The eight-output refusal is the shape of the arrays, not a measured bound on the
channel-count byte, so a session that ever carries nine outputs shows up as skipped calls.
