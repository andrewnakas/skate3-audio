# sub_82B2F798

Args: r3 = an object nothing in `docs/rw_audio_structs.h` names. It computes two terms of the form
`n - 10n / log10(x)`, each rounded to single:

- term 1: n = (s32)+408, x = the single at +460;
- term 2: n = the max of 0 and `count` s32 words at +1072; x = the max of 0.0 and `count` singles
  at +1060, where count = the u8 at +1089 (both reductions, same count, up to 255 -- so a count
  above 3 reads the float loop into the s32 array, which is what the original does).

It then stores sum = term2 + term1 at +32 and adds (sum - old +32) into the single at
`(*(r3+12)) + 40`. One caller, the state step at 0x82B2F8E0 (runs when +1092 == 3, then sets it to
4). That caller reads no register result, so the mask is kReturnNone.

Callee: **sub_82F55068** (log10) twice, through GuestCall with f1 set. It is ported and verified;
its `Windows()` has an empty write set, so it adds nothing here. I mirrored its read list from
`recomp/src/audio_ports/sub_82F55068.inc` (the log pools). Census: gate1 pass, closure
{82F55068, 82F54ED8}.

Stores: `stfs f4,40(r10)` at *(r3+12)+40, then `stfs f6,32(r31)` at r3+32, in that order.
Constants: 0x821963E4 = 10.0, 0x82165A10 = 0.0, both read from the dumped image.

Window: two 4-byte spans. The census's `gate2_suspect` is the r10 store: the pointer at +12 is
loaded after both calls. The call chain writes only stack, so it is the entry value. `Windows()`
checks that r3+12 does not lie within 256 bytes below r1 (the chain's reach: 128 + 96 + 16) and
returns false if it does, or if the pointer is null.

Frame: `stwu r1,-128(r1)` and the `std`/`lfd` scratch at 80(r1) reproduced, for the same reason
as port_82B43CC0 (the callee chain spills below r1). r31 and f29-f31 are restored from locals.

Gates: none fire. STATUS pending, with only 4 calls per boot.

Unsure: what the two terms mean. The "level" naming in the header is a guess from the arithmetic.
