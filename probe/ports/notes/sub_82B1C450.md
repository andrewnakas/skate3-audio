# sub_82B1C450

- Role: `u32 f(obj*)` — apply a pending setpoint. If `s32[+16]` (applied) equals `s32[+20]`
  (requested) it does nothing. Otherwise it latches the **raw** requested value into `+16`, writes
  the requested value **clamped into `[s32[+8], s32[+12]]`** into a stack slot, and calls
  `sub_828E2F38(obj, &clamped)` to notify. Returns 0 on both paths. 60 lifted lines, one callee,
  no own indirect call, no imports, no timebase, no lock. **316,972 boot calls** on
  `RwAudioCore Dac` — the busiest of this batch (tier D).
- Argument: r3 = the object. r4-r10 are not read on entry. All four compares are **signed**
  (`cmpw`).
- The clamp asymmetry, reproduced as lifted: `+16` receives the *unclamped* value while the
  notification receives the clamped one. So the object can hold a value outside its own bounds.
- Stores: one to the object, three to this call's own frame.
  - `stw r11,16(r3)` — `u32[obj+16] = requested`, 4 bytes. The only store outside the frame.
  - `stw ...,80(r1)` — the outgoing by-ref argument, 4 bytes. Reached **twice** on the
    `requested >= low` path: the high bound is stored first and overwritten with the requested
    value when it is in range. Store order preserved; the frame is reproduced because the callee
    reads this slot through r4.
- Result: `li r3,0` on both paths. Mask `kReturnR3`.
- Gate 1 **fails** at depth 1, in `sub_828E2F38` (skate3_recomp.47.cpp:4747, 109 lines, otherwise
  a leaf): it walks a handler list from `[r11+0]` and calls `u32[node+8]` through `mtctr`/`bctrl`
  at **0x828E2FCC** with `(&clamped, u32[node+12])`, looping until the `next` pointer is null.
  That is an observer broadcast: an unbounded number of calls through function pointers, to code
  chosen at runtime, so it can neither be replayed nor bounded. It also relinks the list head
  (`stw r10,0(r30)`) before dispatching. The failure is on every path where the setpoint actually
  changed, i.e. every interesting call.
- The write set I WOULD have declared if it were comparable: `spec.write(r3 + 16, 4)` and
  `spec.read(r3 + 8, 16)` — that is the whole of this function's own footprint, enumerable from
  entry state and one span wide. Everything unenumerable comes from `sub_828E2F38`'s handlers,
  which is the same reason gate 1 bites. Windows() returns false and is unreachable.
- Unsure: whether `+8`/`+12` are `{low, high}` or `{min, max}` of a different sense — the code
  only ever uses them as a signed clamp, in that order, so the reading is safe for the rewrite.
  Address neighbour of `sub_82B1C4B8` (a stepping cursor with bounds at `+0`/`+4` and a probe at
  `+20`); whether the two act on the same type is **not** established, and the offsets differ, so
  no name was borrowed.
