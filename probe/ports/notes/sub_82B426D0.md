# sub_82B426D0 — scatter-mix a routing table, then zero the untouched destinations

Arguments: r3 = eight destination `float*` slots, r4 = eight source `float*` slots, r5 = the number
of destination slots the caller owns, r6 = floats per buffer, r7 = a two-byte inclusive
`[first, last]` route range, r8 = the route-byte table. Void.

This is the routine `probe/ports/notes/sub_82B31368.md` refers to as "the sub_82B426D0 table's
destination index". Each route byte packs three fields, all three identities checked over all 256
byte values rather than read off the rotate-and-mask:
- bits 0-2 (`route & 7`) destination slot, also the flag index
- bits 3-5 (`(route >> 1) & 0x1C`) source slot, times four
- bits 6-7 (`(route >> 4) & 0xC`) gain index, times four, into a four-float table

Gain table address: `lis r11,-32241 ; addi r24,r11,-10560` → `((-32241 & 0xFFFF) << 16) - 10560` =
**0x820ED6C0**, computed, not eyeballed.

Body: clear eight flag bytes at sp+80; for `index` in `[first, last]` (the *last* byte reloaded from
`r7+1` every iteration), call `sub_82B44B20` (dst += src*gain) if the destination's flag is set,
otherwise `sub_82B3BED8` (dst = src*gain) and then set that flag from a **reloaded** route byte;
finally, for each of the r5 slots whose flag is still zero, `sub_82EE5E80` (memset) zeroes
`count*4` bytes of that destination.

Stores: `stbu` x8 and `stbx` are all the eight-byte flag array at sp+80..87 — this function's own
frame, kept in a C array because no callee ever gets its address. `stwu` is the frame move, which
is **not** reproduced: nothing outside this function needs the guest stack to have moved. All
guest-visible writes come from the three callees.

Windows: the union, deduplicated, of
- per route: `[dest_ptrs[route&7], + len)` where `len` mirrors `sub_82B3BED8.inc` /
  `sub_82B44B20.inc` — `(count<<2)&~0xF` on the 128-byte-aligned / count%64==0 vector path,
  `(count<<2)&~3` otherwise. The two callees' vector formulas differ only for a negative count
  (`srawi` versus `rlwinm`), so both are computed and the longer declared.
- every one of the r5 destination slots at `count*4` bytes — declared for **all** slots, not only
  the flag-zero ones, so a mis-simulated flag cannot put a memset outside a window.

MIRRORS `recomp/src/audio_ports/sub_82B3BED8.inc` and `recomp/src/audio_ports/sub_82B44B20.inc`:
a change to either port's write set requires a change to `ScaleSpan` here.

Windows returns false when: r7 or r3 is null; r5 > 8 (past eight the closing loop reads flag bytes
the eight-store clear never wrote, i.e. stack residue a native body cannot reproduce — the caller
in `sub_82B31368` already bounds this at 8); a destination pointer is null; a vector-path span is
zero or not a multiple of 128 (the original's loop never terminates there); or any write span
overlaps the route range, the route bytes, or either pointer array — all three are re-read inside
the loop, so an overlap means the trip count and destinations are not entry state (gate 2).

Gates: 1 pass (three callees, all pure array math or memset; no allocation, lock, indirect call or
timebase — `sub_82EE5E80` is the same memset `sub_82B34E08.inc` already calls); 2 pass under the
guards above; 3 pass; 4 pass. STATUS pending.

Unsure: whether `r3`/`r4` really always have eight slots. The alias check treats both as 32 bytes,
which is conservative in the safe direction (it can only make Windows refuse), but a caller passing
a shorter array adjacent to a destination buffer would be refused rather than compared.
