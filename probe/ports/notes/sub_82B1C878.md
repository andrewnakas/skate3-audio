# sub_82B1C878

Leaf, 50 lines, no callees, no imports, no timebase. Called 244,802 times per boot session on
`RwAudioCore Dac`. Reached through a function pointer: no `bl 0x82b1c878` anywhere in the lifted
tree, the address appears only in the function table, so no call site was readable. r3 is loaded
from `+4` on every exit path immediately before `blr`, so it is the return value: mask `kReturnR3`.

Object (r3; nothing in `docs/rw_audio_structs.h` names it): u16 at +0 = byte offset of a flag
table relative to the object (u32 per entry); u8 at +2 = entry count; u32 at +4 = the selected
value (also returned); u32[] at +8 = the value table, indexed by the flag entry found.

Behaviour: if count == 0, return u32[+4] with no store. Otherwise scan flag[i] for i in
[0, count) (the count is reloaded from +2 each iteration, as the original does; `cmpw` signed).
First non-zero flag[i]: store u32[+8 + 4i] to +4, then return u32[+4]. None non-zero: return
u32[+4] unchanged. A "pick the first active slot's value" selector; which structure it belongs to
is unknown (the census's gate-2 "suspect" is a false positive: the provenance heuristic tied the
store's r3 to the `lwz r3,4(r3)` on the not-found return path, which never flows into the store).

Store: `r3+4` (u32), found path only. Window: `{r3+4, 4}` unconditionally -- covering it on the
paths that do not write it is harmless. Reads: `{r3, 8 + 4*count}` and `{r3 + u16[r3], 4*count}`.

Address arithmetic: the flag address is `u16 + r3` in 64 bits but only its low 32 are used; the
found-path `rlwinm` is `(i+2)*4` (i <= 254, no wrap) and `lwzx` sums u32 -- both reproduced as
plain u32 arithmetic on `object`.

Gates: 1 pass (leaf), 2 pass (4 bytes, entry-derived, bounded reads), 3 pass, 4 pass (store + r3).
Unsure: only the caller identity and the object's real name; neither affects the compare.
