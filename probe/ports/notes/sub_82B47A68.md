# sub_82B47A68

- Role: `slot* acquire(manager* r3, double f1 priority, u32 r5 release_cb, u32 r6 key)` — hand back
  a 32-byte slot in the manager's table. Three outcomes: (a) an in-use slot whose `u32[+16]` is a
  nonzero value equal to `key` — bump `u16[+24]` and return it, touching nothing else; (b) the
  first slot with `u8[+26] == 0` — claim it; (c) no free slot — find the slot with the smallest
  `f32[+8]`, ties broken by the smallest `f64[+0]`, and steal it **only** if that score is strictly
  below the requested priority *and* strictly below the pool float at `0x820ED57C`; stealing calls
  `u32[victim+12](u32[victim+16])` first. Refusal returns 0, as does `u8[manager+49] != 0`.
  438 lifted lines, no direct callees (leaf), one indirect call, no imports, no timebase, no lock.
  22 boot calls on `RwAudioCore Dac` (tier D).
- Manager: `+0` clock object (its `f64[+8]` is the stamp), `+4` slot array, `u8[+48]` slot count,
  `u8[+49]` closed flag. Slot: `f64[+0]` stamp, `f32[+8]` score, `u32[+12]` release callback,
  `u32[+16]` key, `u16[+24]` uses, `u8[+26]` in-use. None of it is named in
  `docs/rw_audio_structs.h`; the names in the port are local to this site.
- Stores, all into one slot (plus the `stwu` back chain, which is the frame and not a window):
  - match path: `sth` `u16[slot+24]`, 2 bytes.
  - claim path (free slot): `stfs [slot+8]` 4, `stw [slot+12]` 4, `stb [slot+26]` 1,
    `stw [slot+16]` 4, `sth [slot+24]` 2, `stfd [slot+0]` 8 — **in that order**.
  - steal path: the same six bytes ranges in a **different order**: `+8`, `+16`, `+12`, `+26`,
    `+24`, `+0`. Both orders are reproduced literally; they are not merged into one helper.
- Constants, each `((imm & 0xFFFF) << 16) + offset`: `lis -32208` + `-31232` + `2112` =
  **0x822F8E40**, the f64 the tie-break starts from; `lis -32241` + `-10884` = **0x820ED57C**, the
  f32 ceiling a stolen slot's score must be under.
- Deviation of form, not of semantics: the minimum search is unrolled four wide in the original
  plus a scalar tail, five copies of the same test sequence with no stores and no calls in any of
  them. The port keeps one `ConsiderSlot()` and two counted loops. The split constant is
  `r7 = ((count-4) >> 2 + 1) << 2 = count - count%4` for `count >= 4` and 0 below it, so the
  unrolled half covers slots `0..r7-1` and the tail `r7..count-1`: the union is the ascending walk
  in order, which is what the port does. That identity is the one thing to re-check if this ever
  becomes comparable.
- Float branches are written in their negated form (`bge` = *not* less, `bne` = *not* equal) so an
  unordered compare refuses, matching `fcmpu`. A NaN priority therefore finds nothing and returns 0.
- Result: **r3**, the slot pointer or 0. On the match path r3 is the walk pointer itself.
- Gate 1 **fails** at depth 0: the `bctrl` at **0x82B47D04** calls the victim's own release
  callback, read from `u32[victim+12]`, with the victim's key in r3. It is a real teardown on live
  state and cannot run on rewound memory, so `Windows()` returns false. Nothing else here blocks:
  no imports, no locks, no timebase, and the function is a leaf otherwise.
- The write set I WOULD have declared: the whole claimed slot, `spec.write(slot, 28)` — but the
  slot is only known after two walks whose bound (`u8[manager+48]`) and array (`u32[manager+4]`) are
  both readable from entry state, so a conservative version could declare all `count` slots
  (`count <= 255`, over the 32-span budget above 32 slots) or predict the walk. Gate 1 is the
  blocker, not gate 2, on the two paths that do not steal.
- Unsure: whether `f64[+0]` is a timestamp at all. It is only ever copied from `clock+8` and only
  ever compared against another slot's copy, which is consistent with a monotonic stamp used as an
  age tie-break, but nothing here proves it is time rather than a sequence number. `+12` is
  confidently a function pointer — it is loaded into ctr — and `+16` is confidently its argument.
