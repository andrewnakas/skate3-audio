# sub_82B33780

- Role: `void f(obj*, index, bytes*, length)` — decode one packet header for stream `index` through
  `sub_82B470D0` into frame scratch, then scatter the seven decoded fields into two per-stream
  records: a 48-byte slot inside the object and an 80-byte entry in the array at `u32[obj+96]`. On a
  non-positive length or a null byte pointer nothing is decoded: both records are zeroed and the
  entry's state byte is set to 1 instead of the decoded byte. 127 lifted lines, one direct callee,
  closure of 8, no imports, no indirect call, no lock, no timebase. 1,932 boot calls,
  `RwAudioCore Dac`. One call site, which ignores r3.
- Address arithmetic, the part most likely to be got wrong: `rlwinm rX,index,1,0,30` and
  `,2,0,29` are 32-bit rotates whose masks clear exactly the bits rotated in from the top, so they
  are the low word doubled and quadrupled. The two `add`s that follow are **64-bit on the full
  index** (`mr r11,r4` copies all 64 bits), and only the next `rlwinm` truncates — hence the
  64-bit intermediates in the port, cast at the stores. Net: slot = `obj + u16[obj+464] + 48*index`,
  entry = `u32[obj+96] + 80*index`, each computed with the low-word wrap the original has.
- Stores. Decode arm, in this order: `slot+36`, `slot+32`, `entry+60`, `entry+64`, `entry+56`,
  `entry+68`, `entry+77` (1 B), then **`slot+36` is RELOADED** and `slot+28 = 0`,
  `entry+20 = reloaded`. Empty arm: `slot+32`, `entry+60`, `entry+64`, `entry+56`, `entry+77 = 1`,
  `slot+28`, `slot+36`, all zero. The reload is reproduced: if the entry record overlapped the slot
  the value would not be what was just stored, and the original would carry that through.
- The `stwu r1,-144(r1)` **is** reproduced: `r1+80` is the output buffer handed to `sub_82B470D0`,
  which allocates 128 bytes of its own below it and whose subtree spills further still. r30/r31 are
  never touched (locals do the job), and `sub_82B470D0` preserves r29-r31 through
  `__savegprlr_29`, so the original's spill/restore pair is a no-op here.
- `sub_82B470D0` through `GuestCall`, **and its whole subtree needs no windows** — read through to
  confirm it, since this is what keeps the function off gate 2. Every store in `sub_82B470D0`,
  `sub_82B471D8`, `sub_82B474B8` and `sub_82B472C0` goes through the r3 it was handed (the buffer at
  `r1+80`, offsets 0, 4, 8, 12, 16, 20, 24, 28 and the byte at 32) or into that function's own
  frame; `sub_82B474B8`'s four `sub_82B47658`/`sub_82B47010` sub-objects all carry a cursor pointing
  at `r1+96` *of 82B474B8's own frame*, so even that family's `*cursor` write stays inside it.
  Nothing in the subtree writes through the byte pointer — it is read-only throughout.
- Window rationale: 4 spans, 33 bytes — `slot+28 .. +39`, `entry+20`, `entry+56 .. +71`,
  `entry+77`. The union of both arms is declared rather than the arm predicted; the addresses come
  from the entry registers plus `u16[obj+464]` and `u32[obj+96]`, both loaded before any store.
  Returns false only when r3 is null. Read set includes `slot+28..39` (because `+36` is re-read) and
  up to 256 bytes of the encoded input for the vector's context.
- Result mask `kReturnNone`: r3 is scratch, and the two arms leave different things in it (the
  reloaded word versus the untouched object pointer), which is itself the evidence that no caller
  reads it — the one call site loads from memory immediately after.
- Unsure: nothing names either record, so "slot" and "entry" are descriptive. The 48- and 80-byte
  strides are read off the index arithmetic, not off a declared type.
