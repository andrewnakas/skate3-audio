# sub_82B47D58

Forty-eight lifted lines; eleven do work. A reference-count drop on the object in r3:
decrement the u16 at `+24`, store it back, and when it reaches zero pass the pointer at `+20`
to `sub_82EC1180` and clear the byte at `+26`.

Arguments: r3 = the object. Nothing else is read.

Stores (both on the entry pointer, `cls=entry` in the provenance):
- `sth r9,24(r3)` -- 2 bytes at `object + 24`, unconditional.
- `stb r11,26(r31)` -- 1 byte at `object + 26`, zero, only on the count-reached-zero path. r31
  is the saved entry r3, because `sub_82EC1180` clobbered r3.

The width detail worth keeping: the count is loaded with `lhz` (zero-extended), decremented as
`addi` in 64 bits, then `extsh` sign-extends the low halfword. The store only ever sees the low
16 bits, so it is the compare that the sign matters for -- a count already at 0 becomes -1,
which is non-zero, so it takes the early exit and never releases. The port reproduces that
rather than treating the count as unsigned.

Gate verdict: **gate 1**, at depth 1, `sub_82EC1180`, which calls
`__imp__RtlEnterCriticalSection` / `__imp__RtlLeaveCriticalSection`. Two reasons it cannot be
replayed: the lock would be taken a second time, and the call *is* the release -- whatever
`sub_82EC1180` frees or returns to a pool is gone before the rewind, so a second run would
release it twice. It is reached only on the count-zero path, so a `Windows()` that predicted
`remaining != 0` from entry state could have returned true on the common path and false on the
release path -- the brief allows exactly that split. I did not do it: with 19 calls per boot
there is no useful volume on either branch, and the split would only ever compare the
two-byte decrement.

Write set that would have been declared if it were comparable: `{r3 + 24, 2}` and
`{r3 + 26, 1}` -- the second only on the release path, and harmless to declare on both since a
byte the call does not write compares equal anyway. Reads: `{r3 + 20, 4}`. Everything
`sub_82EC1180` itself writes is outside that and not enumerable, which is the other half of why
this is not comparable.

Result mask: `kReturnR3`, but nominally. All three call sites
(`skate3_recomp.67.cpp:16018`, `:18208`, `:54007`) ignore r3 and immediately null out the
caller's own `+16`, `+20`, `+28` -- so the function is void and `kReturnNone` would be the
honest mask. r3 is declared anyway because the gate label means nothing is compared, every
other gate-labelled port in the tree declares r3, and comparing r3 would not produce a false
divergence: on the early-exit path the port leaves the entry r3 untouched exactly as the
original does, and on the release path it leaves the callee's.

Those three call sites are also the confirmation of the role reading: each one loads a pointer,
tests it for null, calls this function, and then clears its own handle triple.
