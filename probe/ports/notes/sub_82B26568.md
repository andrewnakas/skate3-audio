# sub_82B26568

The high-pass twin of sub_82B27E20: one channel-bank stage on a 256-frame block, over the same
object and stream layout. Args: r3 = the filter object, r4 = the stream. Returns 1 in r3 on
every path. Read that note first -- everything below is the difference.

Object: +42 u8 channel count, +52 f32 cutoff numerator, +56 four state words per channel
(16 bytes, at most eight -- (184-56)/16), +184 five coefficients, +204 f32 the cutoff they were
built from. Stream: +28/+32 the ping-pong descriptors, +40 format; format+12 f32 sample rate.
Descriptor: +4 float* of channel 0, +14 u16 stride in floats.

Cutoff = float(float(obj+52 / rate) * [0x820B411C]), same expression. The polarity is inverted
throughout:

- **bypass** when `bgt` is false: cutoff <= the floor [0x822F8E7C], NaN included. (sub_82B27E20
  bypasses at the *ceiling* instead.) If the cached cutoff at +204 was itself above the floor,
  four state words per channel are zeroed; then +204 = cutoff, r3 = 1, return. **No descriptor
  swap**, so the caller keeps reading +28: that is the pass-through.
- **filter**: clamp *down* to the ceiling [0x822F8E80] when strictly above it.

The coefficients are built **inline** here, not through sub_82B43CC0, but from the same four
pool constants (0x8209975C, 0x8231A844, 0x82094178, 0x82060C50) and the same sin/cos pair. The
only algebraic difference from sub_82B43CC0 is `fadds f9,f11,f0` where the low-pass has
`fsubs f9,f0,f11` -- (1+cos) against (1-cos) -- and the word at +12 is negated (`fneg`).

Stores: obj+56+16i .. +71+16i (4 x f32 per channel, both paths); obj+184, +188, +192, +200, +196
**in that order, not ascending**; obj+204; stream+28 and stream+32; and per channel 1024 B at
dst written by sub_82B43AF8 plus the same four state words.

Callees, all through GuestCall: **sub_82F4DED0** (sine) and **sub_82F4DFB0** (cosine), which
write only their own frames -- the same pair sub_82B269C0's verified port calls -- and
**sub_82B43AF8** (writes r4..r4+1023 and r3+0..15; saves/restores f20-f31 via __savefpr_20 and
touches no r26-r31). None allocates, locks, signals or calls indirectly; the census gives the
closure gate1 = pass, depth 0. sub_82B43AF8's scalar fallback sub_82B43978 is **unreachable from
here**: it is entered only when the count is zero or not a multiple of eight, and the count is
the literal 256 (`li r7,256`).

Window rationale: identical to sub_82B27E20 -- the union of both paths, all enumerable at entry,
because the channel count, both descriptors and the format pointer are read before the first
store and nothing this call writes can change them (every store lands above obj+56, in the two
descriptor *slots*, or in the output block; a descriptor's own bytes are never written). False
on a null object, stream, format, descriptor or buffer base, and on a count above eight (which
would run the state array into the coefficients: a corrupted object). Budget at eight channels:
11 spans, 8352 bytes.

Deliberate reproductions:

- `fmr f30,f31` is **dead** -- f30 is never read again and the epilogue reloads it, so the port
  leaves ctx.f30 at its entry value. The three f-registers the original spills (f29-f31) and
  r26-r31 are saved and restored, because the callees clobber the volatile file and the harness
  compares f14-f31 and r13-r31.
- `fdivs f9,f4` is issued **twice** (to +192 and +200) on identical operands. Kept as two
  divides; IEEE division is deterministic, so the two words are equal by construction.
- `addi r3,r3,16` runs **after** the call, on whatever sub_82B43AF8 left in r3. It leaves r3
  untouched, so the walk works; the port reads `ctx.r3` rather than incrementing a local, so a
  future port of sub_82B43AF8 that writes r3 would change both sides together.
- `mullw` then `rlwinm x,2,0,29` then `add` is a 64-bit add of two zero-extended halves; kept in
  64 bits through to the GuestCall argument, truncated only at the store addresses.
- `fneg` is reproduced as a sign-bit XOR on the doubleword, not an arithmetic negate.
- `li r3,1` sits **after** the swap stores here (at loc_82B26724), unlike sub_82B27E20 where it
  sits between the two loads. No observable difference, but kept where the original has it.

Unsure: the eight pool constants were never read out of the image, so they are named by their
role in the expression (kSineGain, kUnit, kCosineGain, kDenomGain), not by value; kUnit and
kDenomGain are almost certainly 1.0 and 2.0 but that is not verified. The loop re-reads the
count from obj+42 on every test; Windows assumes no store in the loop aliases obj+42, which
holds as long as the output block does not overlap the object.

Gate verdict: none fire -- callees replayable, write set enumerable from entry, no timebase, the
result is r3 (always 1; the real output is the window bytes). STATUS pending, awaiting a shadow
session.
