# sub_82B298E0

Non-leaf, 319 lifted lines, 74,878 calls per boot on `RwAudioCore Dac`. Census gate-1 pass, closure
of 2 (`82B3C098`, `82B44D18`), nothing outside it. Only caller is sub_82B29BE0, on the path where a
placement parameter moved and the flag byte asks for a ramp; it sets r3 before its next call, so the
mask is `kReturnNone`.

Arguments: r3 = the mixer-side source object (+444 the live f32[8][8] gain matrix, +748 source
channels, +752 destination channels), r4 = the destination descriptor, r5 = the source descriptor
(both `+4` buffer base, `+14 u16` channel stride), r6 = the caller's **saved** copy of the matrix
(sub_82B29BE0's own r1+96), read and never written.

This is sub_82B29AF0 with a ramp, and the port is deliberately the same shape as
`recomp/src/audio_ports/sub_82B29AF0.inc`:

1. If `(int32)+748 > 0` -- a **signed** test, unlike the two unsigned loop bounds later -- compute,
   for each source row, eight per-destination deltas `(live[i][c] - saved[i][c]) * step` and store
   them in this function's own frame at `r1+80 + 32i + 4c`. `step` is the single at `0x822F87E0`
   (`lis -32208 ; addi -31232 ; lfs 480`). All sixteen loads of a row precede all eight of its
   stores in the lifted body, so the port groups them; the differencing order (2,3,0,5,4,6,7,1) and
   the store order (0,2,3,5,4,6,7,1) are both kept.
2. Source channel 0 into every destination channel with sub_82B3C098 (overwrite), starting at
   `saved[0][d]` and ramping by `delta[0][d]`. The source address here is the descriptor's channel-0
   base with **no** stride multiply, read once before the loop.
3. Source channels 1.. into every destination channel with sub_82B44D18 (accumulate), from
   `saved[s][d]` ramping by `delta[s][d]`.

`+752` is reloaded after every kernel call and the second pass tests **whatever the last reload left
in r11** -- one carried variable, not two, exactly as in sub_82B29AF0. `+748` is likewise reloaded per
outer iteration, and both descriptors' base and stride are re-read per inner iteration.

`stwu r1,-432(r1)` **is** reproduced: the deltas live in that frame at +80 and both kernels spill
below the live r1. The six `stfsx` delta addresses are built as `saved + ((r1+80) - r6)` by six
`subf`; both the subtract and the add are 64-bit on zero-extended words and only the store's u32
truncation is observed, so the port writes the frame-relative address directly.

Stores: the eight deltas per source row (own frame, not windowed) and, per destination channel,
`[dst & ~127, (dst & ~15) + 1024)` -- the union of sub_82B3C098's dcbzl-rounded start and both
kernels' `stvx128` runs, copied from their own ported Windows(). Window: those channel spans, merged
where they abut. Returns false when `+748` exceeds 8 rows (the matrix is 8x8; the frame holds 11 rows
of deltas, so 8 is the tighter bound), when `+752` exceeds 32 channels, when a channel run would wrap
2^32, and when a channel run would cover `+748/+752`, either descriptor's base/stride, or this
function's own frame -- the first three would stop the addresses deriving from entry state, the last
would clobber the deltas mid-call.

Gates: 1 pass (no import, indirect call, lock or allocation in the closure), 2 pass except the guards
above, 3 pass (no timebase), 4 pass (the channel writes are observable). STATUS: **verified** -- the .inc header carries the status and the call count the harness session recorded; this note was written before that session ran.

Unsure of:
- `0x822F87E0` read as the ramp step is an inference from how it is used (the difference over the
  kernels' 64-sample ramp, so 1/64 would fit); `probe/harness/out/image` is empty on this tree, so
  the value was not read. Nothing depends on it -- the body loads it through the guest map.
- The six kernel rodata addresses recorded as reads are copied from sub_82B3C098.inc / sub_82B44D18.inc
  (same TU but higher addresses, so they cannot be referenced): if those change, this list must.
- Nothing in the body: the two loops are a register-for-register transcription, and the carried
  destination count is the one place a reader is likely to "fix" it wrongly.
