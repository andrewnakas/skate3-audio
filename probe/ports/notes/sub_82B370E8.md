# sub_82B370E8

Leaf, 477 lines, **23 calls per boot**, `RwAudioCore Dac`. One argument, r3 = the object. It
reads the byte at `r3+42` and fans out on it: 1, 2, 4, 6, above 6, and anything else
(0, 3, 5) returns having written nothing (`cmplwi cr6,r10,6 ; bltlr cr6`).

Destination: an array of 8-byte entries `{u32 sentinel, float value}`. Three groups of six
entries and, above 6, a two-entry tail per group:

    group 0  dest +48   tail +192   source +272   fsqrts applied
    group 1  dest +96   tail +208   source +304   copied
    group 2  dest +144  tail +224   source +336   copied

Each source block is eight floats. The layout byte selects which slot each source index lands
in: 1 -> slot 1 only; 2 -> slots 0, 2; 4 -> slots 0, 2, 3, 4; 6 -> slots 0..5 from sources
0..5; above 6 -> slots 0..4 from sources 0..4, slot 5 from source **7**, and the tail from
sources 5 and 6. Emission order is group 2, then 1, then 0, ascending slot, with the slot-5
entries and the tail as separate blocks after.

Stores: 48 `stw` of the sentinel and 48 `stfs` of the value, all `r3 + constant`, every one
paired 8 bytes apart. The sentinel is `lis r11,32759 ; ori r11,r11,65521` = **0x7FF7FFF1**,
computed as `((32759 & 0xFFFF) << 16) + 0xFFF1`; it is a NaN bit pattern written with `stw`,
and nothing here establishes what it means.

Window: exact on all five paths. For 6 and above every entry in the range is written, so one
span -- `{r3+48, 144}` for 6, `{r3+48, 192}` above it. The narrower layouts get one 8-byte span
per entry (3, 6 or 12 spans). Reads: the layout byte and the 96-byte source region at r3+272.
Sources (272..367) and destinations (48..239) are disjoint, so no load can read a byte this
function stores -- which is why the port emits each pair as sentinel-then-value even though the
original's intra-pair order varies with register scheduling.

Gates: all four pass. `kReturnNone`: nothing but memory changes, r3 is never modified.

**Verification will be thin.** 23 calls in the boot profile, and the layout byte is a property
of the output device, so one path will run and the other four will not be compared at all. If
the device is 5.1 that is the `layout == 6` path; the 1, 2, 4 and above-6 paths are written from
the lifted form and will stay unexercised. Reading the slots as {L, C, R, Ls, Rs, LFE} explains
all five cases at once -- mono to the centre, stereo and quad skipping slot 1, 7.1 moving the
LFE to source 7 and putting a side pair in the tail -- which is exactly the kind of coherent
story CLAUDE.md warns about. The code is written on slot indices, not speaker names, so nothing
depends on that reading being right. `fsqrts` on group 0 suggests power -> amplitude; also a
reading.
