# sub_82B47010

107 lifted lines. `r3` = one of the four sub-objects port_82B47658 hands it: `{cursor* +0,
accumulated +4, remaining +8, flag +12}`. One step of the run-length layer above the
variable-length integer decoder. Returns `u32[obj+4]`, which sub_82B47658 stores into its result
word -- so `kReturnR3` is confirmed by a real call site, unlike most of this batch.

```
if (s32[obj+8] <= 0):                      # bgt cr6 -- SIGNED; the run is exhausted
    cursor = u32[obj+0]
    len    = sub_82B46EA0(u32[cursor+0], sp+80)
    count  = u32[sp+80]
    u32[cursor+0] = len + u32[cursor+0]    # the pointer is RELOADED after the call
    u32[obj+8]    = count + 1
    u8[obj+12]    = 1
    if s32(count) < 0:                     # a negative code: a repeat run, not a literal one
        u8[obj+12] = 0
        u32[obj+8] = 1 - count             # both fields rewritten; the dead stores stay
    if u8[obj+12] != 0: sub_82B46FB0(obj)  # flag RELOADED from memory, not carried
if u8[obj+12] == 0: sub_82B46FB0(obj)      # reloaded again
r3 = u32[obj+4]
u32[obj+8] -= 1                            # loaded before r3, stored after it
```

Exactly one of the two `sub_82B46FB0` call sites runs on the call that decodes, because the flag
chose which. Follow the flag through the *rest* of the run and the two kinds separate:

- **non-negative code** -> flag 1, run length `count + 1`. The first call site fires once, on the
  decoding call. Every later call of the run takes `remaining > 0`, finds the flag set at both
  checks, calls nothing, and returns the accumulator unchanged. A **repeat** run.
- **negative code** -> flag 0, run length `1 - count`. The first call site is skipped and the
  second fires. Every later call of the run also finds the flag clear and fires the second site
  again, so each returns a freshly advanced accumulator. A **literal** run, one coded delta per
  value.

So `count = 0` is one repeated value and `count = -1` is two individually coded ones.

## Exactness points

- Both compares are **signed** (`cmpwi`): `remaining <= 0` gates the decode, and the sign of the
  decoded word picks literal or repeat. The flag compares are `cmplwi` on a byte.
- `addi r7,r11,1` and `subfic r9,r11,1` are 64-bit on a zero-extended u32, and both results go out
  through `stw`. A count of `0xFFFFFFFF` stores `0` for the first and `2` for the second; the port
  keeps `uint64_t` intermediates and casts at the store rather than adding in 32 bits.
- `addi r11,r11,-1` at the tail, same treatment: `remaining == 0` stores `0xFFFFFFFF`.
- The two `lbz r11,12(r31)` reloads are kept. Neither callee writes `+12`, so they look
  redundant, but they are the original's reads and they matter if the cursor object ever aliases
  this one.
- The `stwu` **is** reproduced: `sp+80` is sub_82B46EA0's output address, and sub_82B46FB0 builds
  its own frame below this one. The `stw r12,-8(r1)` / `std` pair is not -- own frame, uncompared,
  and this body keeps r30/r31 in C++ locals so r13-r31 never move off their entry values.

## Windows

Writes: `{obj+4, 9}` -- `+4` (written by sub_82B46FB0), `+8` and `+12` -- as one span, the same
shape port_82B47658 uses for the same structure; plus `{cursor+0, 4}`, written here and again
inside sub_82B46FB0. Reads: `{obj, 16}` and up to ten stream bytes (two codes of at most five).

sub_82B46EA0's only store is the four bytes at its r4, this function's frame scratch, so it needs
no window. sub_82B46FB0's writes are `{cursor+0, 4}` and `{obj+4, 4}`, both already covered -- and
it reads `u32[obj+0]` itself, which nothing here has changed.

The cursor window is declared only when the cursor is actually dereferenced, which is predictable
from entry state: unless the run is still live *and* the flag is set, either the decode branch or
one of the two sub_82B46FB0 call sites reaches it. A null cursor on those paths is refused. Over-
declaring `obj+4` on the path where sub_82B46FB0 never runs is harmless -- a windowed byte neither
run writes compares equal.

The census marks this `gate2_suspect: 1` for the `stw` whose base is the loaded cursor pointer;
that pointer is readable at entry and no store in the call changes `obj+0`, so it is enumerable.

Gates 1, 3 and 4 clean: the closure is sub_82B46EA0 (a verified leaf) and sub_82B46FB0 (ported in
this same batch); no lock, allocation, indirect call or timebase anywhere in it.

## Uncertain

"Repeat" and "literal" are read off the control flow, not off a symbol, and the reading is easy to
get backwards -- the flag that decides is set on the *decoding* call and then re-read on every
later call of the run, so which branch runs during the decode says nothing on its own. What the
accumulator holds between runs (a delta sum, per sub_82B46FB0) is established; the run semantics
are worth confirming against real stream bytes before anyone builds on them.
