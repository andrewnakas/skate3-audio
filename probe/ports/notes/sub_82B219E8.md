# sub_82B219E8 -- close out a Dac update: budgeted pass, stats snapshot, mixer clock

`r3` = the update context. `+8` is the Dac object, `+44` the sink that `sub_82B44858` drains.
Returns `sub_82B44858`'s `r3`; the caller at `skate3_recomp.67.cpp:9497` compares it against 1,
so the result is a genuine status. Called 18,684 times in a boot session, from two sites.

Sequence, in the original's order:

1. `sub_82B3C2D0()` -- the timed retirement pass (its own port, also gate 3).
2. Copy the Dac's `+8` double (the running mixer clock) into the snapshot block at
   `0x83077630` (`lis r9,-31993 ; addi r6,r9,30256`).
3. Fill the rest of the snapshot: `+8` = the Dac's voice array `+108`; `+12` = the pool
   single at `0x822F87CC` (pool + 460); `+20` = the Dac's live voice count `+280` (u16);
   `+22` = 1 when the byte at `+293` of the object a pointer at `0x8307762C` names is
   non-zero, computed by the `addic`/`subfe` carry idiom, which yields only 0 or 1.
4. `sub_82B44858(sink, snapshot)` -- `mr r4,r6` sets the second argument seven instructions
   before the call, so the snapshot block is passed in, not just published.
5. Mirror the sink's `+44` into the Dac's `+228`.
6. Advance the mixer clock: `Dac+8 = Dac+212 + Dac+8`. `fadd`, **not** `fadds` -- the sum
   stays double and `stfd` writes all 64 bits. The increment comes from an `lfs`, so it is a
   single widened to double before the add.
7. `mftb` and stamp it into the profiler block's `+8` (`0x830BDEC4`), the same cell
   `sub_82B3C2D0` and `sub_82B217F0` write.

The Dac pointer at `context+8` is reloaded on all five uses, as lifted: the snapshot stores
sit between them and the compiler could not prove they do not alias.

Snapshot field names are inferred from use; nothing in `docs/rw_audio_structs.h` names this
block. `+16` is not written here, and the pointer cell at `0x8307762C` sits immediately below
the block, so the real structure may start earlier than `0x83077630`.

## Unverifiable, and why

Gate 3, twice over: `sub_82B1F7E8` directly for the stamp at step 7, and `sub_82B3C2D0` at
step 1, which reads the timebase four more times and stores tick values into the profiler
block and the Dac's `+240`. Two runs of this call cannot agree on those bytes, whatever the
port does, so a shadow comparison can never pass. `Windows()` returns false, which is moot:
the macro never arms the shadow branch for a gate-labelled port.

Gate 1 would also fail with a stubbed clock: `sub_82B44858` makes indirect calls
(`queue.json`: `gate1 fail, reason indirect`), it drains the sink, and its closure leaves the
audio corpus through `82EDF460`, `82EE5E80`, `82EE7460`, `82F4DC60`, `82F52B30`, `82F52FB8`.
`sub_82B3C2D0` adds its own gate 1 (`sub_82B49100` retires voices) and gate 2.

## The write set it would have declared

With `dac = REX_LOAD_U32(ctx.r3.u32 + 8)` and `sink = REX_LOAD_U32(ctx.r3.u32 + 44)`, both
readable before the call:

    spec.write(0x83077630, 23);   // the snapshot: +0 f64, +8, +12, +20, +22
    spec.write(dac + 8, 8);       // the mixer clock, stored as a full double
    spec.write(dac + 228, 4);     // the sink's submitted count, mirrored
    spec.write(0x830BDEC4, 4);    // the profiler's timebase stamp
    spec.read(ctx.r3.u32 + 8, 4);  spec.read(ctx.r3.u32 + 44, 4);
    spec.read(dac + 108, 4);  spec.read(dac + 212, 4);  spec.read(dac + 280, 2);
    spec.read(sink + 44, 4);
    spec.read(0x8307762C, 4);  spec.read(0x822F87CC, 4);

plus, transitively, everything `sub_82B3C2D0` declares (its note lists it) and everything
`sub_82B44858` writes -- the latter is not enumerable from entry state, so a real Windows()
here would have to return false on gate 1/2 grounds even with the clock stubbed.

## Unsure

- Whether the byte at `kStatsOwner + 293` is a "profiling armed" flag or something narrower.
  It is read through a global pointer, so the value is not derivable from the arguments.
- `mr r30,r3` sits three loads after the call to `sub_82B44858`; nothing clobbers `r3` in
  between, so the port captures the result immediately after the call instead.
