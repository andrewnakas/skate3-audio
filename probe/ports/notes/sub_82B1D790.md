# sub_82B1D790

Leaf, 19 lines, no stores, no callees, no timebase. Argument: r3 = the operand block. Reads
three u32 words: `minuend` at +4, `subtrahend` at +8, `floor` at +0. Returns in r3
`max(minuend - subtrahend, floor)` where the subtract is a **64-bit** subtract of two
zero-extended u32 loads and the compare (`cmpw`/`bgelr`) is a **signed 32-bit** compare of the
low words. So when `minuend < subtrahend` the difference carries 0xFFFFFFFF in the high word
while the compare only sees the low word; if that low word still compares `>=` floor, r3 keeps
all 64 bits of the wrapped difference. The port keeps the difference in a `uint64_t` and casts
only for the compare, matching the lifted line for line. Clamped path returns the zero-extended
floor word.

Stores: none. Own frame: none (no `stwu`, no red-zone spills). Callee-saved registers untouched.
r9/r10/r11 and cr6 are volatile scratch, not compared, and not reproduced.

Window: empty. Read set `{r3, 12}`, recorded for replay only. `Windows()` always returns true.

Caller / gate 4: no direct call site exists in the lifted tree (the address appears only in
`skate3_audio_census_all.cpp`). It is **slot 31** (+0x7C) of the function table at guest
0x82FD3600 -- one hit in the decrypted image dump at 0x82FD367C, immediately after slot 30
`sub_82B1D700`. `sub_82B1E290` (TU 67) is the interpreter: it reads an opcode byte at
`record+0`, indexes that table (`r29 = 0x82FD3600`, `rlwinm r11,r11,2`, `lwzx`), calls through
`bctrl` with r3 = the block (r31), and then for every operand pair whose source index is -1
stores the returned r3 back into the block (`stwx r3,r9,r31`). r3 is therefore consumed:
`kReturnR3`. Note the interpreter stores only the low word; the harness compares all 64 bits,
which is stricter and safe here because the body reproduces them exactly.

Gates: 1 pass (leaf, no imports, no locks, no indirect calls); 2 pass (write set empty);
3 pass (no `mftb`); 4 satisfied by `kReturnR3`. STATUS: pending.
boot: 99,090 calls on RwAudioCore Dac.

Unsure: only the semantics, not the exactness -- `max(a - b, floor)` over a three-word operand
block reads like a ring-buffer fill level clamped to a minimum, or a generic saturating
subtract in the same expression-evaluator opcode set as slots 30/36 (`sub_82B1D700` sum-with-cap,
`sub_82B1D198` add). No evidence distinguishes them, so no offset names were invented.
