# sub_82B45B60

- Role: leaf, void, `f(obj* r3, f1, f2, f3, float* gains r6)`. Scales a speaker-gain array by
  `f1*f2`. When `f3 < 1.0`, it first divides that factor by the root of the sum of squares of the
  selected gains (power normalisation). 77,736 calls per boot on `RwAudioCore Dac`.
- Callers: `sub_82B45440`, which tail-returns right after (`__restgprlr_29`), and
  `sub_82B460A0`, which loops with r6 += 32 and r4 += 16 and reads only callee-saved registers
  afterwards. In both, f3 comes from `lfs f3,8(r30)`, where r30 is their r4.
- Object (r3). Nothing in `docs/rw_audio_structs.h` names it: `+56 s32 count` (compared with 6
  and 8, inferred to be the output channel count), and `+172/+176/+180/+184 s32` indices into
  `gains`.
- Normalisation, taken only when `f3 < 1.0f`:
  - The 1.0f is read from 0x8231A844. A NaN f3 skips the normalisation.
  - `sum = g[i176]^2 + g[i172]^2 + g[i180]^2 + g[i184]^2`, as `fmuls` then three `fmadds`.
  - If `count >= 6`, add `g[1]^2` (fmadds). If `count == 8`, add `fmadds(g[5], g[5], g[6]^2)` with `fadds`.
  - Then `scale = f1*f2 / fsqrts(sum)`.
- Stores, in order: five `stfs` to `gains+0,+4,+8,+12,+16` (all five loads come before them).
  Then `count` is reloaded from `obj+56` after those stores, and if it equals 8, `stfs gains+20,+24`.
- Windows: `write(gains, 20)`, or 28 when the entry count is 8 or `gains..+19` overlaps
  `obj+56..+59`. The overlap case exists because the reload follows the stores, so the entry value
  cannot predict it. The reads of the indices and the gains they select are recorded only on the
  `f3 < 1.0` path, because the original touches them nowhere else. Always enumerable, so
  Windows() returns true; one write span, at most 28 bytes.
- Result: none. r3 is untouched and only volatile f0/f4..f13, r4/r5/r7..r11 and cr6 are clobbered,
  which neither caller reads. Mask `kReturnNone`, and the gains window carries the comparison.
- Gates: gate 1 passes (leaf, no imports, no indirect calls, no lock), gates 2 and 3 pass (no
  timebase), and gate 4 passes on the gain stores.
- Unsure:
  - The meaning of `count`, the indices and f3 (reading them as channel count, speaker selection
    and spread is an inference).
  - Operand order is kept as lifted on every commutative `fmuls` (`f13*f0` vs `f0*f10` and so on)
    for NaN propagation, per cookbook rule 4. Whether clang keeps it is not controllable from
    source.
