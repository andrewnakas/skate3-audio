# sub_82B1E290

- Role: the expression-evaluator **tick and interpreter**. `void f(double delta_in_f1)`, leaf in the
  census sense (no `bl`), 212 lifted lines, one `bctrl`. 17,448 calls per boot on `RwAudioCore Dac`.
- Globals, all computed as `((lis_imm & 0xFFFF) << 16) + offset`:
  - `0x830775D8` f32 scale global (the `G` that `sub_82B1D5D0`'s note names), `0x830775DC` f32 the
    delta this period was counted for, `0x830775E0` u32 deltas per period, `0x830775E4` u32 the
    countdown. One 16-byte block off `lis -31993` = `0x83070000`.
  - `0x8231A844` / `0x82FD35F4` the period numerator and denominator, `0x82165A10` = 0.0,
    `0x82256FE8` the scale unit, `0x83036F4C` the list head, `0x82FD3600` the opcode table.
- Flow:
  1. `fcmpu f1, [0x830775DC]`. Equal -> load the countdown and the period from memory and go to 3.
  2. Otherwise cache the delta, form `limit = [0x8231A844] / [0x82FD35F4]`, and count with singles:
     `acc += delta; count++` while `acc + delta < limit`. **Unbounded**: a delta of zero or below
     never advances `acc`, so the original spins forever; a NaN delta leaves after one pass with
     count 1. Reproduced, not guarded. Then `stw count -> 0x830775E0`, and
     `[0x830775D8] = float(float(float(count)) * delta) * [0x82256FE8]` via `std`/`lfd`/`fcfid`/
     `frsp` through frame+80. Countdown and period both become the fresh count.
  3. `addic.` the countdown by -1 (64-bit decrement, cr0 on the LOW word, `stw` of the low word),
     store it, and return unless it hit zero. A countdown of 0 becomes 0xFFFFFFFF and never ticks.
  4. On the tick: reload the countdown from the period, read the list head, and for each node walk
     its record stream.
- **The dispatch** (this is what makes the table slots' `kReturnR3` masks correct). A node is
  `{ +0 next, +8 program, +12 operand block }`. A record is
  `{ u8 opcode, u8 pairs, 2 unread, {u32 src, u32 dst} pair[pairs], u32 block_advance }`.
  Per record: `slot = opcode * 4` (`rlwinm ...,2,0,29` on entry, `rotlwi ...,2` on the back edge --
  identical for a byte), `ctr = [0x82FD3600 + slot]`, `r3 = block`, `bctrl`. So every table slot is
  called as `s32 op(block*)` with the block pointer in r3 and **its r3 consumed**: for each pair
  whose `src` is -1 the interpreter does `stwx r3,dst,block`, i.e. the low word of the op's r3 is
  written into the block at `dst`; any other `src` is a block-to-block copy
  `block[dst] = block[src]`. That is why `sub_82B1D790`, `sub_82B1D1C8`, `sub_82B1D5D0`,
  `sub_82B1D200`, `sub_82B1D198` and `sub_82B1D700` are `kReturnR3` and have no `bl` site.
  After the pairs, `block += block_advance` (a **64-bit** add; addresses truncate to 32 bits only at
  each access) and the next record header is the following word. Opcode 255 ends the stream; the
  pair count is reloaded from `program+1` every iteration, so an op that rewrites its own record
  changes the trip count mid-loop.
- Stores: `stfs 0x830775DC`, `stw 0x830775E0`, `std frame+80` (own frame), `stfs 0x830775D8`,
  `stw 0x830775E4` (twice on the tick), and inside the walk two `stwx` into the operand block at
  `block + dst`. Callee-saved r28-r31 go through `__savegprlr_28`/`__restgprlr_28` at entry_sp-40,
  -32, -24, -16 with lr at -8, all inside the 128-byte frame, so none is a window.
- Result mask: **honest mask is none** -- the function sets r3 on no path. On the tick path r3 is
  whatever the last dispatched op left; on every other path it is the caller's own r3, untouched.
  Declared `kReturnR3` anyway because a false `Windows()` with `kReturnNone` trips lint check 5, and
  because a comparison of the walk path would legitimately want the last op's result.
- Gate: **1, fail**. The `bctrl` at 0x82B1E37C dispatches a word of the data table at 0x82FD3600,
  so the callee set is whatever the program bytes name -- it can be any evaluator op, several of
  which write the block, and none of which the harness can bracket. `Windows()` returns false.
  Gate 2 would also fail on its own: the write set is the union over an unbounded node list of an
  unbounded record stream, with every store address computed from bytes the dispatched ops may
  rewrite mid-walk. Gate 3 passes (no `mftb`).
- Unsure:
  - What the period constants mean. `[0x8231A844] / [0x82FD35F4]` reads as seconds-per-period over
    a unit; the image dump was taken before the globals were set, so no live value was available.
  - The two unread bytes at `record+2`. Nothing in this function touches them; they may be an
    operand-count high byte for a wider form, or padding.
  - The `src != -1` pairs. A copy after the call can only feed a **later** record's op, so the
    program is a scheduled dataflow graph; no evidence pins which offsets are inputs versus
    outputs, so no names were invented for them.
