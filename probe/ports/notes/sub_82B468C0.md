# sub_82B468C0

Non-leaf, 216 lifted lines, 24,393 boot calls, `RwAudioCore Dac`. Census gate-1 verdict: pass,
closure of 4, nothing outside it but `82EE5E80` (memset). Void: no result register is named.

Arguments: r3 = destination `float*` array, r4 = source `float*` array, r5 = destination channels,
r6 = source channels, r7 = floats per buffer. Three call sites, all in `skate3_recomp.67.cpp`
(36339, 46503, 47669); each builds both arrays as **eight** words of its own frame, which is what
`kMaxSlots = 8` rests on and matches the bound `sub_82B31368.inc` already enforces on the same two
counts.

Three paths:

- **loc_82B469EC**, taken when r5 **and** r6 are both in `{1, 2, 4, 6, 8}`: index the pair as
  `8*r6 + r5 - 9` (0..63 for those five layouts) into a 128-byte table of two-byte inclusive
  `[first, last]` route ranges at **0x820ED700**, and hand everything to
  `sub_82B426D0(r3, r4, r5, r7, range, 0x820ED780)`. The route bytes live at **0x820ED780**, 128
  bytes on, which is exactly where `sub_82B426D0`'s r8 table is expected. Both addresses computed as
  `((imm & 0xFFFF) << 16) + offset`, not eyeballed.
- **loc_82B469AC**, when `r6 >= r5` unsigned: `sub_82B3BED8(A[i], B[i], r7)` for i in `[0, r5)`, with
  f1 loaded once from **0x8231A844**.
- **loc_82B46928 falling through**, when `r6 < r5`: the same scale for i in `[0, r6)`, then
  `sub_82EE5E80(A[j], 0, 4*r7)` for j in `[r6, r5)` — the destinations the sources ran out for.

f1 is loaded **before** each loop and never reloaded, so the loop depends on `sub_82B3BED8` leaving
f1 alone. That dependence is reproduced, not papered over.

## The census / notes contradiction, settled

Both are right, about different things, and one existing note is wrong on a detail:

- The census's `stores_present: false` is **literally true of this function's instruction stream**:
  its only store is `stwu r1,-144(r1)`, the frame back-chain (store provenance lists exactly that one
  entry). It says nothing about the transitive set.
- `probe/ports/notes/sub_82B31368.md` is **right**: every guest-visible byte comes from a callee, and
  in that caller's case every destination is 82B31480's own frame scratch.
- `probe/ports/notes/sub_82B31680.md` is **wrong** where it attributes bytes to "`sub_82B426D0` (two
  byte-write loops, one addressed `stbx r6,r8`)". Those byte writes are `sub_82B426D0`'s **own
  frame**: its store provenance resolves both base registers to `addi rN,r1,79/80`, and
  `recomp/src/audio_ports/sub_82B426D0.inc` (verified) keeps them as a C array precisely because no
  callee ever receives their address. `sub_82B426D0`'s guest-visible writes all come from
  `sub_82B3BED8`, `sub_82B44B20` and `sub_82EE5E80`, each of which writes `[ptr, ptr + n)` with n
  from a count register.

Consequence for the two refusals that depend on this: the write set of this subtree **is** enumerable
from entry state, and this port enumerates it. `sub_82B31680.md`'s gate-2 refusal on its delta-flush
arm is therefore over-conservative rather than forced — what a Windows() there would have to do is
simulate the two eight-entry pointer arrays `sub_82B31480` builds in its frame, which
`sub_82B31368.inc` already does. Nothing about that refusal is unsafe; it is simply recoverable.

## Windows

All three paths reduce to "buffers named by the destination pointer array", enumerated per path:

- route path: a mirror of `sub_82B426D0.inc`'s own Windows() — one destination per route byte in
  `[first, last]` sized by `ScaleSpan`, plus **every** one of the r5 destination slots at `4*r7`
  bytes (declared regardless of the flag, so a mis-simulated flag cannot escape a window), plus its
  gain-table and route reads.
- scale paths: `[A[i], A[i] + len_i)` with `len_i` mirroring `sub_82B3BED8.inc` alone.
- zero path: `[A[j], A[j] + 4*r7)`.

Spans are deduplicated (the same buffer can appear under several routes). Returns false when: r3 is
null; r4 is null on any path that reads it; a destination pointer is null; `r5 > 8` on a non-route
path (past eight the arrays are the caller's frame residue, which a native body cannot reproduce);
a vector-path span is zero or not a multiple of 128 (`sub_82B3BED8`'s loop never terminates there,
and the original hangs too); or any declared write overlaps something re-read during the call —
either pointer array, the route bytes (reloaded after each non-accumulating scale) or the route range
(reloaded every iteration). `r5 == 0` returns true with no spans: the call writes nothing.

**MIRRORS three other ports, all in aggregator ports_68a while this file is in ports_68b** — a
different translation unit, so the values are copied rather than referenced (`probe/ports/lint.py`
check 8): `sub_82B3BED8.inc` (the span formula), `sub_82B426D0.inc` (`ScaleSpan`, the route decode,
the 0x820ED6C0 gain table) and, through the second of those, `sub_82B44B20.inc`. A change to any of
their write sets requires a change here.

The `stwu r1,-144(r1)` **is** reproduced, unlike `sub_82B426D0.inc`'s own frame, and for a different
reason than usual: nothing here needs the guest stack to have moved, but every callee spills below
whatever r1 it is entered with, and if r1 sat 144 bytes higher during the replay those spills would
land at different addresses than in the original run — any one of them inside a declared window would
read as a divergence. r25-r31 are never written, so `__savegprlr_25` has nothing to reproduce.

Gates: 1 pass (three callees, all verified ports or plain memset; no allocation, lock, indirect call
or timebase), 2 pass under the guards above, 3 pass, 4 pass (void, and the write set is non-empty
whenever the call writes anything). STATUS pending.

Unsure of: `kMaxSlots = 8` is the three call sites' array size, not a measured bound on r5 — a caller
carrying a ninth channel would show up as skipped calls rather than as a divergence. The route path
passes r7/r8 with the `lis` sign extension still in the high half; `sub_82B426D0` reads only the low
32 bits, so the 64-bit form is reproduced but never exercised.
