# sub_82B33970

Advances voice `index` of the system at r3 to its next buffer. 368 lifted lines, 2070 calls per
boot, `RwAudioCore Dac`. Same two records as `sub_82B33D40`, at the same offsets:
`voice = *(object+96) + 80*index` (r31), `slot = object + u16(object+464) + 48*index` (r28).

Arguments: r3 = system object, r4 = voice index, r5 = an opaque value forwarded to `sub_82B332D0`
and `sub_82B33418`, **r6 = a pointer to one byte of output** — set to 1 when the slot cursor has
already gone negative, 0 on every other path. Returns 1, except 0 when `sub_82B332D0` reports
failure.

Three shapes, chosen by `voice[73]`:
- **0** — when the cursor is exactly 0, seed `voice[52]` from `voice[8]`; then open the next buffer.
- **1** — push one timestamp to `sub_82EC0E08` (skipped only when `voice[76] == 1` and
  `voice[28] == 0`), republish the cursor into `voice[20]`, then `sub_82B332D0`.
- **anything else** — publish the cursor, and if it is still short of `voice[16]` open the next
  buffer; then, only while `voice[16] < slot[20]`, push a timestamp and either return (the cursor
  moved back under the watermark) or call `sub_82B332D0`.

Two shared sequences are factored into helpers because they appear verbatim twice:
`PushTimestamp()` (0x82B33A6C and 0x82B33B70 — identical but for the image tag: 0x82B31E90 when
`voice[76] != 0`, else 0x82B31E30; the second site always uses 0x82B31E30) and `OpenNextBuffer()`
(0x82B339E4 and 0x82B33B0C — identical but for one store, the cursor republish, which only the
first site makes because the second path already did it at loc_82B33AE0). Both take `uint8_t* base`.

Stores: `*r6` u8 (1 or 0); `voice+52` u32; `voice+74` u8; `voice+20` u32 (up to three times);
`voice+48` u32. Frame-internal: `r1+80` as a u32 zero, a u64 integer spill and a u64 float spill.

`loc_82B33B44`'s comparison is the carry lowering (`rlwinm` sign bits, `subfc`, `subfe`, `and 1`)
of a plain signed `voice[16] < slot[20]`; worked out by enumeration, including the mixed-sign cases
where an unsigned reading would disagree. The harness does not compare XER, and no other port sets
it, so the carry side effects are not reproduced.

Gate verdict: **gate 1** on every path that calls anything: `sub_82B33418` reaches
`sub_82B3C870`'s `bctrl`, `sub_82B332D0` reaches the same, and `sub_82EC0E08`'s closure contains
`sub_82EC1290` (`RtlEnterCriticalSection`/`RtlLeaveCriticalSection`). `sub_82B32550` is clean and
is not the reason.

**Worth knowing:** the `cursor < 0` path calls nothing at all — it writes one byte through r6, sets
r3 = 1, and returns. Predicted from entry state (`u32(slot+24)` is readable before the call), it is
a legitimate partial comparison: `spec.write(ctx.r6.u32, 1)` and return true there, false on every
other path, exactly the split the brief allows. It is not wired up here because the macro skips the
shadow branch entirely for a gate-labelled STATUS, so it would need the status changed to pending
and a `Windows()` that returns false for every other cursor value. Whether one predicate's worth of
coverage justifies that is a judgement for whoever picks this up.

Unsure: `voice+16` is named a watermark from being compared against both the slot's cursor (+24) and
its total (+20); the units are not established. `voice+52` is named a start pointer from being
`sub_82B33418`'s second argument, which in `sub_82B33D40` is `voice[64] + voice[8]` — consistent
with a data pointer, not proof. The two 0x82B31Exx tags are never dereferenced on this path.

## Split and armed, 2026-09-12

Wired up the partial comparison this note described, which needed the STATUS changed to pending
before the macro would arm the shadow branch at all.

- **Predicate:** `(int32_t)REX_LOAD_U32(slot + 24) < 0`, with `slot = object + u16[object+464] +
  48*index` computed by the same expression `Native()` uses. That is the function's first test and
  nothing outside the frame is stored before it.
- **One extra decline.** Both bodies store the frame link word at `r1-144` before reading the cursor,
  so `Windows()` refuses if that word overlaps `slot+24` rather than assuming the guest stack and
  the system object are disjoint. It cannot fire in practice; it costs one comparison if it does.
- **Comparable write set:** `{r6, 1}` — the single byte `stb r11,0(r6)` writes on
  `loc_82B33BF4`. Result `r3 = 1`.
- **Expected fraction:** unmeasured, and probably a minority of the 2,070 boot calls: a negative
  cursor means the stream is spent, which is an end-of-buffer condition rather than the steady state.
- **Stays unchecked:** everything else, which is most of the function — all three mode shapes, the
  `voice+52`/`+74`/`+20`/`+48` stores, both `fcfid`/`fctidz` round trips, the two 0x82B31Exx tags,
  and `sub_82B33418`, `sub_82B332D0`, `sub_82B32550` and `sub_82EC0E08`. One predicate's worth of
  coverage, as the earlier draft of this note put it — but it is one predicate more than a gate
  label buys, and the skip count says so on every session.
