# sub_82B33C08

Lifted: `skate3_recomp.67.cpp:53365`, 174 lines. Callees `sub_82EC1290`, `sub_82EC1378`. No
`bctrl`, no `mftb`. Called 1071 times during boot on `RwAudioCore Dac`.

## Arguments

- `r3` the owner object -- the same two arrays `sub_82B33870` addresses: an 80-byte slot array at
  `*(owner+96)` and a 48-byte parallel record at `owner + u16(owner+464)`.
- `r4` the slot index.
- `r5`, `r6`, `r7` three **out pointers**, one word each: data pointer, size/length, and the
  queued buffer (or zero). These are the function's real results.

## The slot fields

| offset | use |
|---|---|
| `+40` | the queue `sub_82EC1290` pops from and `sub_82EC1378` returns to |
| `+48` | the raw read cursor, rewritten on the inline path |
| `+52` | where the cursor restarts when the tag is 69 |

The parallel record contributes exactly one byte: `+47`, which gates whether tag 72 counts as a
control chunk.

## Per attempt

**Queued path** (`+40 != 0`):
```
buffer = sub_82EC1290(*(u32*)(slot+40));   // takes the critical section, pops the queue
*out_buffer = buffer;
if (!buffer) { *out_data = 0; *out_size = 0; return; }
*out_data = *(u32*)(buffer+8);
*out_size = *(u32*)(buffer+4);
```

**Inline path** (`+40 == 0`): the header is read byte by byte off the cursor.
```
cursor = *(u32*)(slot+48);
*out_buffer = 0;                       // stored BEFORE the header loads
tag = cursor[0];
length = (cursor[1] << 16) | (cursor[2] << 8) | cursor[3];   // 24-bit big-endian
*out_data = cursor;                    // the cursor itself, not a payload pointer
*out_size = length;
*(u32*)(slot+48) = (tag == 69) ? *(u32*)(slot+52) : cursor + length;
```

Built as `rotlwi r8,r10,8` then `or`, then `rlwinm r4,r5,8,0,23` then `or` -- two shifts and two
ors, not one load, which is why the port spells out the byte order.

## The tag classification

The data pointer is **reloaded from the out word** rather than reused, then its first byte is
tested against 69, 72 and 85 in that order:

- `header == 0`: return.
- `69`: control -- release and retry.
- `72`: control **only if** `record+47 != 0`; otherwise return.
- `85`: control -- release and retry.
- anything else: return. This is the case the caller wants: a real data chunk.

"Release and retry" is:
```
if (*out_buffer) sub_82EC1378(*(u32*)(slot+40), *out_buffer);   // the queue is RE-READ
goto top;
```
The two release sites in the original (`0x82B33D04` and `0x82B33D28`) are identical instruction
for instruction; the port merges them.

69/72/85 are `'E'`, `'H'`, `'U'` in ASCII. That reading is a reading -- the decimal values are
what the compares use, and no chunk-format document in `docs/` names these three together.

## Gate verdict

**gate-1 at depth 1, twice over.**

1. `sub_82EC1290` takes `RtlEnterCriticalSection` / `RtlLeaveCriticalSection` (census). Beyond the
   lock, it **pops a queue**: the popped buffer is not in any window and a rewind cannot put it
   back, so a replay would drain the queue twice and hand the second run a different buffer.
2. `sub_82EC1378` is the matching release, which frees.

`Windows()` returns false unconditionally.

Gate 2 fails independently and worse: the retry loop is **unbounded**. Every control chunk sends
it back to the top, so the number of queue pops, the number of cursor advances and therefore the
write set are all unknowable from entry state. The census marks seven stores `gate2_suspect`.

## Return mask

`kReturnR3`, declared because a gate-labelled port with `kReturnNone` and no `spec.write()` trips
lint check 5. The honest mask is the three **out words** `*r5`, `*r6`, `*r7`, plus `slot+48`;
`r3` carries nothing deliberate -- there is no `li r3,...` on any path, so it holds whatever the
last load or call left. If this ever became comparable, the right declaration would be
`spec.write()` on the three out words and `slot+48`, with no result register at all.

## Uncertainties

- Neither `sub_82EC1290` nor `sub_82EC1378` was read; "pop" and "release" come from the call
  shapes (one argument in, a pointer out; two arguments in, nothing out) and from the buffer's
  `+4`/`+8` being read as a size and a data pointer.
- The three tags are decimal compares. The ASCII reading and whether this is the same chunk stream
  `docs/` describes elsewhere were not established. If it is, the 24-bit big-endian length here is
  worth comparing against the open question about the chunk length field's low bit -- this site
  reads three whole bytes and uses the value as a byte advance with no masking, which is evidence
  against a bit-offset reading but was not pursued.
- `*out_data` gets the cursor itself on the inline path and the buffer's `+8` on the queued path.
  Whether the caller treats those the same way (it must, since it reads `[0]` as the tag either
  way) means a queued buffer's `+8` also points at a chunk header.
- `slot+52` as a rewind target is inferred from the tag-69 arm alone.
- Whether the `+47` gate on tag 72 is a feature flag or a stream-state bit is unknown.
