# sub_82B30C50

Non-leaf, 958 lifted lines, 18,684 calls per boot on `RwAudioCore Dac`. This is the DAC's output
frame: source channels in, interleaved little-endian 16-bit out, into the device buffer. No static
caller in the lifted tree (it is reached through a pointer), so the result mask is taken from the body:
`li r3,1` on every path, `kReturnR3`.

Callees, all four replayable (no import, no indirect call, no lock, no timebase anywhere in the
closure -- each was read, not assumed): `82B468C0` (ported, the channel gather), `82B43FB8` (ported,
the linear resampler), `82F52FB8` (a small memcpy: writes only its r3 run), `82EDF460` (a VMX memcpy
via `82EE7460`/`82F52FB8`: `std`, `stbu`, `stvlx128`, `stvrx128`, all into its r3 run).

Arguments: r3 = the device object, r4 = the stream (`+28` the source descriptor, `+40` a format record
whose `+12` is the source sample rate).

Device fields used: `+8` -> `*` -> a **bump allocator** whose `+32` is the top; `+42` u8 source
channels; `+80` f32 device rate; `+84` u32 destination channels; `+88` non-zero skips the conversion;
`+92` zero means the whole call is a no-op; `+100` f32 / `+108` s32 the cached rate ratio and its 16.16
form (clamped to `0x40000`); `+104` singles per channel in the resampled bank; `+112` the leftover
phase; `+116`/`+120` the device buffer's capacity and the bytes produced; `+128` u16 the offset within
this object of the per-channel history (24 bytes, six singles, per channel); `+130` u16 bytes per
interleaved frame; `+132` the device buffer; `+136`/`+137` u8 history counters.

Flow, once `+92` is non-zero:

1. Fill a pointer table at `r1+96` with the source descriptor's channels at its stride.
2. If the source and destination channel counts differ: allocate `align128(dest * 1024)`, fill a
   second table at `r1+128` with its 1024-byte slices, gather through sub_82B468C0 (which is handed
   r6 = the source count **without the caller setting it** -- it is still live from `lbz 42(r3)`), then
   memcpy the second table over the first, so everything downstream reads the gather block.
3. If the stream and device rates differ: recompute `+100`/`+108` when the ratio moved (single divide,
   multiply by the rodata at `0x820B4114`, round half away from zero through `fctiwz`, signed clamp to
   `0x40000`); allocate 1152 bytes of history scratch and `align128(+84 * +104 * 4)` for the resampled
   bank; work out how many frames this pass can make (`(((budget+1) << 16) - +112 - 1) / +108`, or
   8192 when `+108` reads zero, or none when the budget is non-positive -- the `twllei` divide-by-zero
   trap sits behind that test and is unreachable); then per channel: copy the history tail in front of
   1024 fresh bytes, resample into the bank row, and copy whatever the resampler did not consume back
   into the channel's 24-byte history row (an unrolled four-at-a-time loop plus a memcpy remainder).
   Publish `+136` and `+112`, and memcpy the bank pointers over the source table.
4. Allocate `align128(+130 * +84 * frames)` for the output block. If that comes back zero, skip to the
   releases. Otherwise, unless `+88` is set, convert each channel: clamp each single to
   `[0x8216DEE0, 1.0f]`, multiply by the full-scale single at `0x821747FC`, `fctiwz`, and store the low
   halfword **little-endian** at `output + 2*(frame*channels + channel)` -- four frames per trip plus a
   remainder loop.
5. Publish `+120` (clamped by `+116`), copy the block into `*(+132)`, and give all four blocks back to
   the allocator, newest first, each only if it was taken. Return 1.

The `stwu r1,-352(r1)` **is** reproduced: both pointer tables, sub_82B43FB8's two out-parameters
(`r1+80` index, `r1+88` phase) and the `stfd`/`lhz`/`sth`/`lbz` conversion scratch all live in that
frame. The conversion round trip is modelled as arithmetic rather than through the frame, since it is
this function's own frame and nothing else reads those bytes; the two output bytes are written low
first, which is what makes the buffer little-endian.

## Gate 2, and what a window set would need

The body is written and faithful; `Windows()` returns false and the port is labelled `kPortGate2`, so
it is counted and never compared. The write set is *shaped* from entry state -- the allocator word, four
scratch blocks, the history rows, six object words, and the device buffer -- but it cannot be *named*
before the call:

1. Three of the four block sizes depend on `frames`, which comes from a `divwu` by `+108`, and `+108`
   is itself rewritten earlier in the same call out of a single-precision divide, a rodata multiply, a
   round-half-away-from-zero and a signed clamp. A window builder would have to re-derive all of that
   exactly; one bit wrong puts a store outside the windows, which is the only failure mode that
   reaches the live game.
2. sub_82B468C0's and sub_82B43FB8's ported `Windows()` both read their pointer arrays out of memory,
   and the arrays are the two tables this call fills. Before the call those slots hold last frame's
   values, so mirroring those callees means predicting the tables rather than reading them.
3. The budget. Six channels at 256 frames is roughly 6 KB + 1152 B + 6 KB + 3 KB of scratch plus ~3 KB
   for the device buffer: about 20 KB of the 32 KB cap before the object rows. Eight channels fits only
   just, and the `+108 == 0` fallback asks for 8192 frames, which is ~98 KB in the output block alone.

The one comparable path is the early exit (`+92 == 0`): it writes nothing and returns 1. A future pass
that wants it can relabel the port `kPortPending` and return true for exactly that case. It was left
out deliberately: a session would then mark this port "verified" on the strength of the empty path,
which is the false green the gate labels exist to prevent.

## Unsure of

- Field names are read off use, not symbols: `+80`/`+12(format)` as rates, `+104` as the bank's row
  length, `+130` as bytes per interleaved frame, `+128`/`+136`/`+137` as the history triple.
- No rodata value was read (`probe/harness/out/image` is empty on this tree). `0x820B4114` is
  consistent with 65536.0f and `0x821747FC` with a full-scale 16-bit multiplier, but neither was
  checked; the body loads both through the guest map.
- The bump allocator is an inline pointer decrement on a guest structure, restored by this same call,
  not a call to an allocator -- so it is gate-2 material (the write set), not gate-1 (replayability).
- The four unrolled conversion slots store `+0` before `+1` in some copies and after in others; they
  are two bytes of one halfword with no read between, so the order is not reproduced.
- The history copy-back writes `16*(((left-4)>>2)+1)` bytes at the channel's 24-byte row plus a memcpy
  remainder; at `left > 6` that runs into the next channel's row, and for the last channel past the
  region. Reproduced as written -- it is also one of the things a window set would have to bound.

## Split and armed, 2026-09-12

Reversing the decision recorded above: the port is now `pending (partial: ...)` with `Windows()`
returning true for the early exit and false for the working path.

- **Predicate:** `REX_LOAD_U32(device + 92) == 0`. It is the function's first test, ahead of anything
  but the frame, and `Windows()` reads it through the same `kActive` constant `Native()` uses, so the
  two branch together by construction. That matters more than usual here: on an empty write set, a
  predicate that disagreed with the body would let the working path's stores land outside the windows
  and reach the live game.
- **Comparable write set: empty.** The early exit writes only its own 352-byte frame, which the brief
  excludes, and returns 1.
- **Expected fraction:** unmeasured, and plausibly small — 18,684 calls a boot, and `+92` reads as
  the device-active flag, so the steady state is the working path. It could be zero.
- **Stays unchecked:** the entire 958-line body: the two pointer tables, the gather, the resampler and
  its history rows, the 16.16 ratio recompute, the little-endian conversion, the device-buffer copy
  and all four bump allocations. This comparison covers the guard, the frame discipline, r14-r31 and
  f31 surviving `__savegprlr_14`/`__restgprlr_14`, and `li r3,1`.
- **Why the earlier objection no longer applies.** It was that a session would report this port
  "verified" on the strength of an empty path. The STATUS line now names the predicate, and the
  hook's skip counter reports the uncompared calls on every session, so the green is labelled
  instead of being prevented. The gate-2 reasoning for the working path is unchanged and stays in
  the comment above `Windows()`, because that is where the next person will look.
