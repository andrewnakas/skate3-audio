# sub_82B31480

- Role: `void f(voice*)` — release a voice from its mix list. Two arms, selected on
  `u8[voice+78]` (the node's own gain count): non-zero flushes the eight per-channel gains into
  the owner and clears them; zero does the same unlink with no flush. 193 lifted lines, two
  direct callees, closure of 6, no imports, no indirect call, no lock, no timebase.
  5,967 boot calls, `RwAudioCore Dac`. Four call sites: `sub_82B31368` (a tail branch),
  `sub_82B315E0`, `sub_82B31680`, `sub_82B31720`.
- Arguments: r3 = the voice. `u8[+41]` a source-channel count, the node at `+56`
  (`+0` next, `+4` prev, `+8`, `+12` list token, `+16` owner, `+20` u16, `+22` u8 gain count —
  the same word as `voice+78`), `u32[+80 .. +108]` the eight gain words.
- Fold arm (`u8[+78] != 0`). Builds two eight-entry pointer arrays in its own 208-byte frame —
  `sp+112..140` pointing at frame scratch `sp+144..172`, `sp+80..108` pointing at
  `&voice[+80 .. +108]` — then `sub_82B468C0(sp+112, sp+80, u8[+78], u8[+41], 1)`,
  `sub_82B34BD0(voice+56, sp+144)`, then eight `stwu` zeroes over `voice[+80 .. +111]`.
  Stores above r1: `sub_82B34BD0`'s set, plus `voice+80 .. +111` (32 B).
- Unlink arm (`u8[+78] == 0`), guarded by `u32[node+12] != 0` — `sub_82B34BD0` inlined with a null
  gain vector: `u32[owner+4] = u32[node+0]` when the node is that head, `u32[next+0] = u32[node+0]`,
  `u32[prev+4] = u32[node+4]`, then `node+12`, `node+16`, `node+8` (4 B each), `node+22` (1 B),
  `node+20` (2 B). Same order, same reloads as 82B34BD0.
- The `stwu r1,-208(r1)` **is** reproduced (unlike most ports' frames): `sub_82B468C0` allocates
  144 bytes of its own and spills r25-r31 and lr through `__savegprlr_25`, which would land on the
  two pointer arrays if they stayed in this function's red zone. The low word is assigned on its
  own and the closing `addi r1,r1,208` is a 64-bit add, exactly as lifted, so r1 (compared) comes
  back bit for bit. The r12/r30/r31 spills at the caller's -8/-16/-24 are not reproduced; r30/r31
  are never touched, so their exit values are their entry values either way.
- **The fold arm's write set IS enumerable — recorded because `sub_82B31680` refused gate 2 on
  exactly this arm.** `sub_82B468C0`'s whole subtree writes only into *this* function's frame:
  every destination it hands `sub_82B3BED8` / `sub_82B44B20` / `sub_82EE5E80` is an entry of the
  `sp+112` array, i.e. a word of `sp+144..175`, and each of those writes exactly
  `[dst, dst + 4*n)` with `n` the literal 1 passed in r7 — so never `sub_82B3BED8`'s `dcbzl`
  vector path or `sub_82B44B20`'s, both of which need `n % 64 == 0`. `sub_82B426D0`, reached when
  both counts are in {1,2,4,6,8}, picks its source and destination indices as `(byte>>1)&7` and
  `byte&7` out of a read-only table pair at `0x820CD700` / `0x820CD780` (`lis -32241` + `-10496` /
  `-10368`, computed) and keeps its visited flags in its own frame, so it also stays inside the
  eight entries. The gains are the SOURCE side throughout. `sub_82B31680` could not say this
  because from ITS entry state the destinations are a frame 82B31480 has not built yet; from
  82B31480's own entry state they are its own frame, which is exempt from windowing. The same
  conclusion is already carried, verified, by `port_82B31368`, which windows this function through
  its tail branch — this port's `Windows()` is deliberately the same code.
- Window rationale. The arm is predicted from `u8[voice+78]`, entry state, nothing written before
  it. Fold arm: `UnlinkWindows(node, fold=true, count)` plus `voice+80 .. +111`. Unlink arm:
  `UnlinkWindows(node, fold=false, 0)`. At most 8 spans, ~70 bytes. Returns false when the voice
  is null; when either count exceeds 8 (past eight entries the original reads pointers out of the
  uninitialised part of the frame and stores through them — those addresses are not entry state);
  and when the owner pointer or the node's gain count lies inside the folded gain range, since
  `sub_82B34BD0` re-reads both inside that loop.
- Frame scratch is fully initialised before it is read on every path, so the two harness runs feed
  `sub_82B34BD0` identical gains: `sub_82B426D0`'s flag array starts zeroed, so the first visit to
  an index copies (`sub_82B3BED8`) and only later ones accumulate (`sub_82B44B20`), and its closing
  loop memsets every index below the count whose flag is still zero.
- Result mask `kReturnR3`. r3 is not a return value the three ordinary callers read, but
  `sub_82B31368` tail-branches here, so r3 becomes that function's result. It is exactly
  derivable: `voice+56` on the fold arm (`sub_82B34BD0` never writes r3), the entry value on the
  unlink arm.
- Unsure: nothing names this structure, so voice/node/owner are descriptive only. A null owner
  with a non-zero list token is reproduced, not guarded — the original would store to `0x2E`; that
  matches `port_82B34BD0` and `port_82B31368`, both verified, rather than adding a guard they lack.
- Gate verdict: **no gate on either arm** (gate 1 pass per the census, gate 2 as argued above,
  no timebase, r3 named). STATUS pending: written, never compared.
