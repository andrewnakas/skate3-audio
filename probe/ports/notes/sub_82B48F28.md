# sub_82B48F28

- Role: `int f(object*, uint32 flag)` — destroy an object. Three phases: release every non-null
  child in the array at `+80` (count `u8[+68]`, stride 4) through two vtable entries per child,
  slot `+0` with `(child)` then slot `+12` with `(child, 0)`; then, only when `flag & 0xFF == 0`,
  unlink the list node embedded at `+28` from one of the owner's (`u32[+16]`) five heads, chosen
  by `u8[+71]`; then free the object through `u32[u32[u32[owner+36]+0]+12](allocator, object, 0)`.
  258 lifted lines, one direct callee (`sub_82B49438`), three own `bctrl`, no imports, no
  timebase, no lock. 2,152 boot calls on `RwAudioCore Dac` (tier D).
- The type-byte dispatch is split in two by `sub_82B49438`'s verdict, which is the part worth
  writing down: **1 → owner+20** and **3 → owner+28** run *before* the call; then
  `sub_82B49438(object)` runs unconditionally, and only if its **low byte** is 0 do
  **2 → owner+16**, **4 → owner+24**, **5 → owner+32** run. Type 0 unlinks from nothing. Both
  halves end in the same two-store splice. The type byte is reloaded across the call.
- Stores (nine, plus the `stwu` back chain):
  - `stw r10,20(r9)` / `stw r10,28(r9)` / `stw r10,16(r9)` / `stw r10,24(r9)` / `stw r10,32(r9)`
    — 4 bytes each, one head of the owner, only when that head still equals `object+28`
  - `stw r9,0(r10)` and `stw r11,4(r10)` twice over — 4 bytes each into the node's two
    neighbours, the splice
  - the `stwu` back chain and `__savegprlr_28`'s r28..r31 + lr spills are this call's own frame.
- Window rationale: `Windows()` returns **false**, and it would have to even without gate 1 —
  the per-child vtable calls write whatever each child's implementation writes, which is not
  knowable from entry state. So gate 2 fails one level down as well, exactly as
  `probe/ports/notes/sub_82B49238.md` predicted.
- Result: r3 is whatever the allocator's free entry returned — there is no `li r3,...` on any
  path. The macro line carries `kReturnR3` because a gate-labelled port with a false `Windows()`
  and `kReturnNone` trips lint check 5; the honest mask is **`kReturnNone`** and it is never read,
  since the macro does not arm the shadow branch for a gate label.
- Gate 1 **fails at depth 0**, three times: `bctrl` at **0x82B48F6C** (child acquire slot `+0`),
  **0x82B48F84** (child free slot `+12`) and **0x82B490F0** (the object's own free). The last one
  is on every path, so no entry state avoids it. The child pair additionally means a replay would
  release every child twice.
- Unsure: the `+0`/`+12` vtable pair is read as acquire-then-release by analogy with
  `sub_82B49280` and `sub_82B32870` (`+12` is the allocator free entry there); the first slot's
  meaning is not confirmed. Which concrete lists the five heads are is unknown — only that they
  are five distinct four-byte heads at owner `+16..+32` and that the type byte picks one.
  `kPrev`/`kNext` for node `+0`/`+4` are borrowed from `sub_82B34BD0`, which has the same head
  update and the same splice; the directions there were never independently confirmed either.
