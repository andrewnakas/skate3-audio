# sub_82B26740

Non-leaf, 263 lifted lines, 30,114 boot calls, `RwAudioCore Dac`. Census gate-1 verdict: pass,
closure of 5; outside it only `82B43978` (sub_82B43AF8's odd-count fallback) and `82F4DED0`/`82F4DFB0`
(sin/cos, reached through sub_82B43D78). Mask `kReturnR3`: `li r3,1` on both paths.

Arguments: r3 = the source object, r4 = the two-entry buffer-descriptor pair — the same pair
`sub_82B29BE0` and `sub_82B34E08` swap, `+28` the side read FROM and `+32` the side written INTO,
plus `+40` a format record whose `+12` is the mixer's rate.

Object layout, all plain offsets: `+42` u8 channel count (**reloaded every loop iteration**, both
loops); `+52` f32 the source's own corner; `+60` f32 the shelf gain; `+64` f32[4] per channel, the
biquad history `sub_82B43AF8` carries; `+192` s32 an "engaged" flag; `+196` f32[5] the coefficients
`sub_82B43D78` builds, ending exactly at `+216`; `+216`/`+220` f32 the (corner, gain) pair those
coefficients were built for. The histories run from `+64` and the flag sits at `+192`, so **eight is
the object's own channel limit** — that is where `kMaxChannels` comes from, not from a measurement.

Behaviour. `corner = fmuls(fdivs(f32[+52], f32[u32[r4+40]+12]), 0x820B411C)`.

- `corner < 0x822F8E80` **and** `f32[+60] != 1.0`: set `+192` to 1 if it was 0; floor the corner at
  `0x822F8E7C`; if `(corner, gain)` differs from the cached pair, call
  `sub_82B43D78(self+196)` with f1 = corner and f2 = gain (still in f2 from the compare) and publish
  the pair — with the gain **reloaded** from `+60` rather than kept in f2; then for each channel
  `sub_82B43AF8(self+64+16i, out_i, in_i, self+196, 256)`; then swap `+28`/`+32`, both words
  **reloaded** there.
- otherwise: if `+192` is exactly 1 (a signed compare), zero the histories with the constant at
  `0x82165A10` — four singles per channel through three `stfs` and one `stfsu` — and clear `+192`;
  either way publish `(corner, f32[+60])` into `+216`/`+220`. No channel is touched and the pair is
  **not** swapped.

Constant-pool addresses, each `((lis_imm & 0xFFFF) << 16) + offset`, computed: `0x820B411C` the ratio
scale, `0x822F8E80` the limit, `0x822F8E7C` the floor, `0x8231A844` = 1.0, `0x82165A10` = 0.0. The
pool base `0x822F8600` derived here independently agrees with `sub_82B43AF8.inc`'s `kPool`;
`0x8231A844` with `sub_82B43D78.inc`'s `kOne`; `0x82165A10` with `sub_82B269C0.inc`'s `kZeroFloat`.

## Stores

Own: `+192` (4, both paths, different values), `+216` and `+220` (4 each, both paths), the two pair
words (8, filtering path only), and the history clear `[+64, +64+16*channels)` (bypass path only).
Through callees: `sub_82B43D78` writes exactly `[+196, +216)`; `sub_82B43AF8` writes its 16-byte
history block (`self+64+16i`) and exactly `[out_i, out_i+1024)` — a scalar biquad, no `dcbzl`, no
alignment widening, so the span is its `count*4` and nothing wider. The `stfd f31,-64(r1)` spill and
`__savegprlr_26` are the function's own frame and are not reproduced: f31 and r26-r31 are never
written by the native body, and both callees preserve them.

## Windows

One span per part: `[+64, +64+16*channels)`, `[+192, +224)` (the flag, the coefficients and the two
cached singles in one), `[+28, +36)` on the pair, and one 1024-byte span per destination channel.

The path is **not** predicted. Choosing it needs the `fdivs`/`fmuls` at the top of the function, and
running that float work inside `Windows()` would execute it under the guest's FPSCR before the
original does, for no gain — so both paths are declared and a byte a path did not write compares
equal anyway. The cost is that a bypass-path call is refused when a descriptor is null, which is why
the non-null test is the honest edge rather than a necessity.

Returns false when: r3 or r4 is null; `u8[+42] > 8`; either descriptor is null; any declared span
would wrap 2^32; or any declared span overlaps something re-read while the call runs — `u8[+42]`, and
each descriptor's `[+4, +16)` (base and stride, both re-read on every iteration) — or overlaps
another declared span. That last check is stricter than strictly needed (overlapping destination
channels would still be enumerable) but it can only make `Windows()` refuse, never miss a byte; with
the usual 256-single stride consecutive channels abut exactly and it passes. Budget: at most 11 spans,
8 KB + 168 bytes.

**MIRRORS** `recomp/src/audio_ports/sub_82B43AF8.inc` (the `[out, out+count*4)` plus 16-byte history
write set, and the `kPool + 432` bias it reads) and `recomp/src/audio_ports/sub_82B43D78.inc` (the
20-byte coefficient block and its three other pool constants). Both are in aggregator ports_68a while
this file is in ports_67a — a different translation unit, so the values are copied rather than
referenced. `ChannelAddress` is copied from `recomp/src/audio_ports/sub_82B29BE0.inc`, which is in
**this** aggregator but at a higher address, so it is included after this file and cannot be
referenced either (`probe/ports/lint.py` check 8). A change to any of the three requires a change
here.

The `stwu r1,-144(r1)` **is** reproduced, for the same reason as `sub_82B468C0.inc`: both callees
spill below whatever r1 they are entered with, and if r1 sat 144 bytes higher during the replay those
spills would land at different addresses than in the original run.

Unsure of: the meaning of `+52` versus the format's `+12` — the quotient times a pool constant reads
as a normalised corner frequency, and the `sub_82B43D78` port's own note identifies the coefficients
as an RBJ high shelf at S = 1, which fits, but nothing here confirms it. Why the filtering path
reloads `+60` for the cache instead of storing the f2 it just used is unexplained; it matters only if
another thread moves `+60` mid-call, and it is reproduced rather than tidied. `kSamples = 256` is a
literal `li r7,256`, so the 1024-byte channel span is exact rather than assumed.
