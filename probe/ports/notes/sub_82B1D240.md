# sub_82B1D240

Arguments: `r3` = the object. Returns 0 in `r3` when `+8` is null at the end, otherwise the
clamped state -- or `sub_82B1F5F8`'s result, which overwrites it on the state-1 path. Lifted at
skate3_recomp.66.cpp:66296, 228 lines. **957,760 calls at boot** on `RwAudioCore Dac`: this is
one of the hottest functions in the corpus, a per-tick state pump rather than an event handler.

Flow: clamp `+24` to 0..2 into r30. If it equals the sign-extended `+12`, everything up to
`loc_82B1D378` is skipped. Otherwise, with `instance = u32[self+8]`:

- state 0 and an instance: the instance vtable's **slot 0** through `bctrl`, then `u32[self+8] =
  0`, then `sub_82B1F440(self)` -- which sees the null it just wrote, so only its bookkeeping
  runs (its own note: it releases `+8` through slot 0 and zeroes the stride-12 slot `+14` picks).
- state 1 and an instance: the vtable's **slot 8** through the shared `bctrl` at `loc_82B1D364`.
- state 1 and no instance: skipped entirely when the latched state is 2 **and** `+13` is 1 --
  i.e. a resume out of a suspend that never had an instance. Otherwise index `+20` into the table
  at `+4`, and if the record's halfword tag at `entry+4` is `0xFFFF` store 0 to `+8` (already 0)
  and call `sub_82B1F440`, else call `sub_82B1F4C8(self, entry+4)` and store its `r3` to `+8`.
- state 2 and an instance: the vtable's **slot 4** through the same shared `bctrl`.

Then `loc_82B1D36C` reloads `+12`, stores r30 there and the reloaded byte at `+13`. Then, if the
state is 1 and `+8` is now nonzero, `sub_82B1F5F8(self)` runs and its result replaces r30. Then
`+8` is loaded a third time; null returns 0, otherwise the vtable's **slot 24** is called and r30
is returned.

Index clamp, reproduced arithmetic-for-arithmetic:
- `index >= count` (signed) -> `count - 1` as a **64-bit** value, so `count == 0` leaves
  `0xFFFFFFFFFFFFFFFF` in r11 and the masked multiplies below carry that through to
  `table + 0xFFFFFFF4`. Not guarded, because the original does not guard it.
- `index < count` -> `((index >> 31) & 1) - 1` masked against the index, which clamps a negative
  index to 0.
- `index*3` is `index + ((index << 1) & 0xFFFFFFFE)`, a 64-bit `add` on masked-to-32 operands;
  `*4` is `(low32 << 2) & 0xFFFFFFFC`; the final `add r11,r11,r9` is 64-bit and the address is
  taken as `.u32`.

Stores: `+8` u32 (three sites), `+12` u8, `+13` u8. Plus the frame: the r29/r30/r31 spills at
entry_sp-32/-24/-16, the link word at entry_sp-8 and the back chain at entry_sp-112, all inside
the 112 bytes this call allocates, so none of them is a window.

Window rationale: the write set is small and fully enumerable -- `spec.write(self+8, 4)` and
`spec.write(self+12, 2)` would cover it, three spans at most. Enumerability is not the problem.

Gate verdict: **gate 1**, at depth 0 -- this function's own three `bctrl` sites, not a callee's.
`0x82B1D2A8` is the instance vtable's slot 0, which `sub_82B1F440`'s note identifies as the
release entry, so a shadow replay would release the instance twice. `0x82B1D368` is the shared
slot-8 / slot-4 site and `0x82B1D3BC` the slot-24 poke. On top of that, both named callees are
themselves gate 1 (`sub_82B1F440` at `0x82B1F474`, `sub_82B1F5F8` at `0x82B1F66C` plus six more
through `sub_82B1BE30`), and `sub_82B1F4C8` allocates the instance whose pointer is stored to
`+8` -- four independent reasons the harness can never bracket this call.

Result mask: `kReturnR3`, which is what the function actually returns. (Lint check 5 rejects
`kReturnNone` on a port that declares no writes; there is nothing to reconcile, because r3 is
genuinely the result.)

Uncertain:
- The record table is read as stride 12 from `table + 0`, yet the clamp limit is the u32 at
  `table + 0` as well, so entry 0's first word and the count are the same bytes. Either the
  index is 1-based in practice or the clamp of a negative index to 0 is a latent bug. Not
  resolved here.
- `sub_82B1F4C8` reads `r4+0`, `+3`, `+4`, `+5`, `+6`, `+7` and `+8` -- with `r4 = entry+4` that
  last read is `entry+12`, one byte past the 12-byte stride. Either the stride is larger than the
  index arithmetic implies or the records share a trailing byte. Unresolved.
- The state values are named release/resume/suspend from the vtable slots and from
  `sub_82B1F440`'s recovered role, not from any symbol.
