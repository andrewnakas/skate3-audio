# sub_82B33F98

- Role: `void f(self*, int index)` — cancel one slot. This is the function that makes
  `sub_82B32328` (and, through it, `sub_82B32870`, `sub_82B33210` and the rest of that family)
  fail gate 1 transitively: it is `sub_82B32328`'s only callee and it carries an indirect call of
  its own. 210 lifted lines, three direct callees (`sub_82B3C930`, `sub_82B32480`,
  `sub_82B47D58` — **all three already ported and all three gate-1**), no imports of its own, one
  `bctrl`, no timebase. 1,925 boot calls on `RwAudioCore Dac` (tier D), which tracks
  `sub_82B3C930`'s 1,926 almost exactly: the decoder release is the common path.
- Arguments: r3 = the ~478-byte record every port in this family calls `self`, r4 = the slot
  index. Addressing is the usual pair, both `rlwinm`+`add` chains reproduced in 64 bits:
  the 48-byte **record** = `self + u16[self+464] + 48*index`, the 80-byte **slot** =
  `u32[self+96] + 80*index`.
- What it does, in order:
  1. `u32[record+8]` nonzero → `sub_82B3C930(that)` (the decoder teardown) then `u32[record+8] = 0`.
  2. The **cancel scan** over the 20-entry, 16-byte ring at `self+100`, driven by a **third**
     cursor: `+473` is the claim cursor (`sub_82B32550`), `+475` the retire cursor
     (`sub_82B32480`), and `+474` is this one. While the entry's class byte `+14` equals the slot
     index and its state byte `+13` is neither 2 (already finished) nor 0 (free), it writes state
     **2** and advances `+474` with the same `subfic`/`subfe` wrap-at-20 idiom `sub_82B32550` and
     `sub_82B32480` use. State 2 is exactly what `sub_82B32480` retires, so this marks the slot's
     in-flight buffers for release rather than releasing them itself.
  3. `sub_82B32480(self)` — run the retire pass immediately.
  4. `u32[slot+36]` nonzero → `sub_82B47D58(that)`, a refcount drop.
  5. `u32[slot+28]` nonzero → free it through the owner's allocator:
     `u32[u32[u32[self+8]+36]+12](allocator, buffer, 0)`. **The same owner/allocator/vtable+12
     triple `sub_82B32870` uses**, which is now a third independent sighting of it.
  6. `u8[record+46] = 0` — the byte `sub_82B332D0` tests for exactly 1 to arm its staleness check.
  7. The tail block, gated on `u8[slot+75] == 1` **and** `u8[holder+71] == 0` where
     `holder = u32[self+12]`: copy the float at `holder+40` to `holder+48`, set `holder+71 = 1`,
     and push the 8-byte node at `holder+28` onto the list whose head is `u32[u32[holder+16]+20]`
     (node+0 = old head, node+4 = 0, old head+4 = node, head = node).
- Stores (10 outside this call's own frame):
  - `stw r26,8(r29)` — `u32[record+8] = 0`, 4 bytes, only when a decoder was released
  - `stb r9,113(r11)` — `u8[ring entry+13] = 2`, 1 byte, **up to 20 times** in the scan
  - `stb r6,474(r31)` — `u8[self+474] = wrapped cursor`, 1 byte, once per scan iteration
  - `stb r26,46(r29)` — `u8[record+46] = 0`, 1 byte, unconditional
  - `stfs f0,48(r11)` / `stb r8,71(r11)` / `stw r7,28(r11)` / `stw r26,32(r11)` — the holder's
    `+48`, `+71`, `+28`, `+32`, tail block only
  - `stw r10,4(r11)` — `u32[old head+4] = node`, only when the list was non-empty
  - `stw r10,20(r9)` — the list head
  - the `stwu` back chain and the `__savegprlr_26` spills are this call's own frame.
  Two reloads are load-bearing and reproduced: the cursor at `+474` is re-read **twice** per scan
  iteration (once for the entry, once for the increment), and the list head at `+20` is re-read
  **after** the two node stores instead of being reused from r7 — which matters only if a node
  word can alias the head, but the original does not assume it cannot.
- The float at `holder+40 -> +48` is a `lfs`/`stfs` pair through the double register. The port
  keeps the same `double(f32)` / `float(f64)` round trip the lifted form has, and the single
  `ctx.fpscr.disableFlushModeUnconditional()` stays immediately before the load. No arithmetic
  happens to the value; it is a latch, not a computation.
- Result: **none.** No `li r3,...` on any path; r3 is left holding whatever the last call returned
  (or the freed buffer's allocator result). The macro line carries `kReturnR3` because a
  gate-labelled port with a false `Windows()` and `kReturnNone` trips lint check 5 (a vacuous
  comparison); the mask is never read, since the macro does not arm the shadow branch for a gate
  label. A comparable version would declare `kReturnNone` plus the write set above.
- Gate 1 **fails four times over**, and on every path:
  1. depth 0, its own `bctrl` at **0x82B340A4** — a heap free through a vtable slot;
  2. `sub_82B3C930` — four indirect calls (already labelled gate-1 as a port);
  3. `sub_82B32480` — `RtlEnterCriticalSection`/`RtlLeaveCriticalSection` via `sub_82EC1378`, and
     it is called **unconditionally**, so even a call that releases nothing is unreplayable;
  4. `sub_82B47D58` — the same lock via `sub_82EC1180`.
  The write set itself is perfectly enumerable from entry state (the ring scan is bounded at 20
  entries, and every address is a load off `self`), so this is gate 1 and not gate 2. If the
  harness ever grows a way to stub a lock, this function's `Windows()` would be writable.
- Unsure: what the holder at `self+12` is. The `+28` node pairs with the `+0`/`+4` link words
  `sub_82B34BD0` unlinks, but that port's head lives at `owner+4` and this one's at `list+20`, so
  they are not obviously the same list — that was not chased. The float latch from `+40` to `+48`
  reads like "remember the value in force at cancel time", which is a guess. `u8[slot+75]` and
  `u8[holder+71]` are both tested for exact values and only ever written here, so the rewrite is
  safe whatever they mean.
