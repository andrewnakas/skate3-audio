# sub_824531C8

Leaf VMX128 kernel, 113 lines, 43 vector instructions, **7,402,130 calls per boot session** --
the hottest function in the audio set by two orders of magnitude.

Four-lane sine. It loads four 16-byte coefficient vectors from 0x822F97C0..0x822F9850, reduces
the argument in v1 by `round(x * scale)` using a negative multiply-add, then evaluates an
11-term odd polynomial in t^2 by Horner with one fused multiply-add per term. The result is left
in v1.

**This is the gate-4 function `docs/execution-trace.md` names.** It has zero stores and its
result lives in v1, which is neither in `SHADOW_PRESERVED_VRS` (v14-v31, v64-v127) nor reachable
by the old three-flag `ShadowReturn`. Comparing it would have checked nothing at all on eight
million calls -- a total vacuous green. The `ShadowResults` mask added this session names it as
`Vr(1)`, so the comparison is now real. That extension is what makes any register-only kernel
checkable, not just this one.

Two details the port preserves deliberately:

- Every `vmaddfp` is a single-rounding FMA and every `vmulfp128` is a separate multiply. Writing
  the Horner chain as `a*b+c` in source would let the compiler contract a multiply and an add
  into one FMA and change the result.
- The function clobbers v31, which the ABI would preserve, so the native body reproduces that
  value too. The harness compares v31 on every call regardless of the mask.

The `vspltw128` immediates look wrong until you remember the lane reversal: word 3 splats with
0x00, word 2 with 0x55, word 1 with 0xAA and word 0 with 0xFF. They are copied from the lifted
form rather than re-derived.

At 7.4M calls per session this is also the measurement for the plan's open question about shadow
overhead: three `PPCContext` copies per call on the audio thread. Watch the `Audio stats`
real-time figure in the session that arms it; `SKATE3_PORT_EX`'s sample shift is the fallback.
