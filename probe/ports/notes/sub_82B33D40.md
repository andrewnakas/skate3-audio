# sub_82B33D40

Starts voice `index` of the system at r3. 333 lifted lines, 1932 calls per boot, `RwAudioCore Dac`.

Arguments: r3 = system object, r4 = voice index, r5 = an opaque value forwarded untouched to
whichever starter runs (held in r26 across the body).

Two derived records, both computed from entry state only:
- `voice = *(object + 96) + 80 * index` (r31) — `rlwinm r4,2`/`add`/`rlwinm ,4` is `index * 5 << 4`.
- `slot  = object + u16(object + 464) + 48 * index` (r27) — same shape with `* 3 << 4`.

Flow: when `voice[76] == 1` and `slot[47] == 0`, `sub_82B33C08` fills three frame slots
(`r1+80`, `r1+96`, `r1+88`); a zero in the first returns 0 immediately. Otherwise `sub_82B335A8`
runs, and when `slot[24] >= 0` two timestamps are pushed to `sub_82EC0E08` —
`fcfid(extsw(voice[12])) + double(voice[0])`, `fctidz`'d back to an integer, both round-tripped
through the frame exactly as lifted. Then `sub_82EC1378` if `voice[40] != 0`. After that, always:
`sub_82B48840(object[8])` returns a registry, and its intrusive list (link at container + 16) is
walked for a container whose `+20` equals `*(0x82119870 + 4 * voice[72])`. `sub_82B3CD38` turns the
match (or 0) into a handler; no handler means `slot[40] = 255` and return 0. With one, the flag byte
is 1 unless `slot[36]`, `slot[32]` and `voice[60]` are all zero, and `voice[73]` picks the starter:
0 or 2 goes to `sub_82B32550` + `sub_82B33418`, anything else to `sub_82B332D0`.

Stores (all outside the frame): `slot+40` u32 (twice on the no-handler path, 0 then 255),
`slot+8` u32 (the handler, and 0 again if `sub_82B332D0` failed), `slot+44` u16,
`voice+74` u8, `voice+48` u32. Frame-internal: `r1+80` u64/u32, `r1+96` u64, plus the `stwu` word.

The frame IS reproduced — `sub_82B33C08` takes pointers into it and the timestamp round trips use
it as scratch — but `__savegprlr_26`'s spills are not: the body keeps r26–r31 in locals and never
writes those registers, so `Leave()` restores lr from the entry value instead of reloading it.

One hazard worth naming: at `loc_82B33F48` the lifted does `mr r8,r5` *after* `bl 0x82b32550`,
reading a volatile register back across a call. It works only because `sub_82B32550` happens never
to write r5 (checked: it touches r3, r6–r11 only). Reproduced off the context, not from the local,
so it stays wrong the same way if that callee ever changes.

Gate verdict: **gate 1**, four independent reasons, and at least one on every path.
`sub_82B33C08` -> `sub_82EC1290` takes `RtlEnterCriticalSection`/`RtlLeaveCriticalSection`;
`sub_82B3CD38` has four `bctrl`; `sub_82B33418` -> `sub_82B3C870` has one; `sub_82B3C930` has four.
The path that skips the preamble still reaches `sub_82B3CD38` unconditionally, so no path is
comparable. Windows() therefore returns false and was not written out; had it been, the write set
above is enumerable from entry state in 6 spans, so this is *not* also a gate-2 function — the
label is gate 1 alone.

Unsure: `voice+28`/`voice+40` are named "sink" from their use as the first two arguments to the two
0x82EC helpers, which are outside the audio corpus; the subsystem's role is not established here.
`0x82B31E90` (the fifth argument to `sub_82EC0E08`) is a fixed image pointer whose contents are
never read on this path. `sub_82B48840` is outside the census, so its own gate status is unknown —
it is not the reason for the label.
