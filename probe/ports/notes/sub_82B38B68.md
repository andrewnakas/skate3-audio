# sub_82B38B68

46 lifted lines, no stores of its own, no frame: a two-way dispatcher ending in two tail branches.
No static call site in the lifted corpus, so the 30395 boot calls arrive through a function
pointer.

Arguments: r3 a coefficient pair, r4 the sample count, r5 the "accumulator already primed" flag,
r7 a stage descriptor. r6 is not read (the first thing the function does is overwrite it with r3).

```
bypass = u32[stage+8]
if bypass == 0:                      # b 0x82b389a0
    sub_82B389A0(n   = r4,           # mr r3,r4
                 c   = u32[stage+0], t   = u32[stage+4],
                 d   = u32[stage+16], acc = u32[stage+20],
                 primed = r5,        # r10
                 a = f32[coeffs+16], g = f32[coeffs+20])
else:                                # b 0x82f52040
    memset(u32[stage+20], 0, (r4 << 2) & ~3)
```

So `stage+20` is both the stage's accumulator and the buffer the bypass path clears, and `stage+8`
is the bypass flag. The argument mapping is what identifies the fields: port_82B389A0 already
names its own r6/r7/r8/r9 as c/t/d/acc, and this is where those four pointers come from.

Native: both paths keep their callee behind `GuestCall`. Both are `b`, not `bl`, so LR still holds
this function's own return address and the callee returns straight to our caller -- GuestCall does
not touch LR, which is the same state. Two details reproduced rather than skipped, because the
original leaves them set when it branches: `r11 = stage` (`mr r11,r7`, not an argument register, so
it is assigned directly), and on the bypass path `r6 = coeffs`, `r9 = bypass`, r7/r8/r10 as they
stood. memset reads only r3/r4/r5, so none of that changes behaviour; it keeps the two entries
identical machine states instead of nearly identical ones. The single
`fpscr.disableFlushModeUnconditional()` sits where the lifted body has it, before the `lfs f2`,
with none before the `lfs f1` -- matching, not tidied.

`rlwinm r5,r4,2,0,29` is written as `rotateleft32(count, 2) & 0xFFFFFFFC`, the same shape the
lifted body uses: a 32-bit rotate whose two rotated-in low bits the mask clears, so it is
`count * 4` for any count below 2^30 and something else above it. Left as the rotate on purpose.

## Windows

Bypass path: `[acc, acc + (count << 2 & ~3))`, one span. sub_82F52040 was read by hand
(`skate3_recomp.106.cpp:64780`; it is outside the audio corpus, hence outside the census): a
byte-alignment prologue, a 16-byte body, 4- and 1-byte tails, all through one cursor from r3, so
the write set is exactly `[r3, r3 + r5)` and `r5 == 0` writes nothing. It is a leaf, with no lock,
no allocation and no indirect call.

Stage path: port_82B389A0's window set restated with these arguments -- `acc & ~127` rounded up to
whole cache lines when `primed == 0` (the dcbzl clear), then `d & ~0xF` and `acc & ~0xF` for the
loop's own 64-byte ceiling, with c, acc and t (plus one line, for the unaligned tap) as reads.
Refusals carried over from that port: a negative count makes the clear run over gigabytes, and a
count past 2^24 overflows the arithmetic. A count of zero writes nothing on either path.

Gate 1 passes: sub_82B389A0 is a verified pure-arithmetic kernel, sub_82F52040 is memset, neither
takes a lock, allocates or calls indirectly. Gate 2 passes with the refusals above. Gate 3 passes.

Result mask `Gpr(3) | Vr(2)`: inherited from port_82B389A0, which names exactly those, and this
function tail-branches into it so its caller sees the same two registers. On the bypass path
memset leaves r3 = the destination and never touches v2; both are identical between runs because
the same callee produces them.

Uncertain: `stage+12` is never read here and is unidentified. The mask is inherited rather than
confirmed from a call site, since none exists statically -- if a divergence ever shows up in v2 on
the bypass path, that is the thing to question first.
