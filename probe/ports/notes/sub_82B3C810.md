# sub_82B3C810

- Role: `this* f(this*, uint32 flags)` — a destructor, instruction for instruction the same
  function as `sub_82B1E3F8` and `sub_82B23C78` with a different vtable constant. It installs the
  vtable pointer `0x8231BAA0` at `*this`, and when bit 0 of `flags` is set it calls
  `sub_828AAF88` for the allocator and dispatches the allocator's vtable slot `+12` (`free`) with
  `(allocator, this, 0)`. It returns `this` either way. 57 lifted lines, one direct callee, one
  own indirect call, no imports, no timebase, no lock. 1,926 boot calls on `RwAudioCore Dac`
  (tier D).
- Arguments: r3 = `this`, r4 = flags (only bit 0 is read, via `clrlwi r10,r4,31`).
- Constant: `kVtable = ((-32206 & 0xFFFF) << 16) + (-17760) = 0x82320000 - 0x4560 =
  **0x8231BAA0**`. Computed, not read off by eye — and worth insisting on here, because
  `sub_82B23C78` has the *same* `lis r11,-32206` and only a different `addi` (`-18140`,
  giving `0x8231B924`). Eyeballing either one would have produced the other's vtable. The lifted
  `lis` leaves `s64 = -2110652416`, the sign extension of `0x82320000`, which confirms it.
- Stores: one outside this call's own frame — `stw r9,0(r3)`, 4 bytes, `u32[this+0] = 0x8231BAA0`.
  The other three (`-8(r1)` link, `-16(r1)` r31 save, the `stwu` back chain) are the frame and are
  never windowed; the frame is still reproduced because both callees run on it.
- Result: r3 = `this` (`mr r3,r31`). Mask `kReturnR3`.
- Gate 1 **fails** at depth 0 — this function's own `bctrl` at **0x82B3C854**, whose target is
  `u32[u32[allocator+0]+12]` called with r5 = 0: a heap free, unreplayable on rewound memory.
  `sub_828AAF88` compounds it: it lazily initialises the heap through `sub_828AB0E8` on first
  call and its transitive closure is 131 functions, all outside the audio corpus. Bit 0 of r4
  predicts the path from entry state, so a Windows() could in principle return true for even
  flags — but that path writes only the vptr and proves nothing about the half that frees, so it
  is not worth a split.
- The write set I WOULD have declared if it were comparable: `spec.write(r3 + 0, 4)` and
  `spec.read(r3 + 0, 4)`, plus the allocator's own set — which is what makes it unenumerable as
  well as unreplayable. Windows() returns false and is unreachable.
- Unsure: nothing about the rewrite. The three siblings being byte-identical apart from the
  vtable is itself the useful finding: whatever class hierarchy this is, its destructors were
  emitted from one template, so a fourth will look the same and can be ported by substitution
  once its two immediates are computed.
