# sub_82B33418

- Role: `u32 f(self*, header*, int index, u32* counter, u8 flag, u8 mode)` — parse one chunk
  header and submit its payload to the decoder. Returns **header + length**, i.e. the next
  header; `sub_82B33870` stores that into `u32[slot+48]`, which makes this the stream walker.
  211 lifted lines, one direct callee (`sub_82B3C870`), no imports, no indirect call of its own,
  no timebase, no lock. 3,110 boot calls on `RwAudioCore Dac` (tier D).
- Arguments, from the two known call sites (`sub_82B332D0` passes its own r5/r6/r7 straight
  through, and `sub_82B33870` calls that with `(…, 1, 0)`):
  r3 = self, r4 = the 8-byte chunk header, r5 = the slot index, r6 = **a pointer to one u32 the
  caller owns** (the only argument this function writes through), r7 = a byte whose zero-ness is
  handed to the callee as a 0/1, r8 = a byte selecting the extra-state path. In the chain
  `sub_82B33870 -> sub_82B332D0 -> here`, r7 = 1 and r8 = 0 always, so **the `mode != 0` path has
  no known caller** in the ports read so far.
- The header, two big-endian words, and the one genuinely interesting thing in this function:
  - `u8[slot+76] == 0`: **length = word(bytes 0..3) & 0x7FFFFFFF** — the top bit of the first
    word is discarded — and count = word(bytes 4..7). Both words are assembled by spilling four
    bytes into the frame at `r1+80..83` and reading them back as one `lwz`; the slot is reused for
    the second word, which is why the port reproduces the spill instead of folding it to shifts.
  - `u8[slot+76] != 0`: **length = bytes 1..3 only** (a 24-bit field; byte 0 is not read at all),
    count = word(bytes 4..7) exactly as above.
  So the header's first word is a length with either **one** flag bit at the top or a **whole**
  flag byte, chosen per stream by `u8[slot+76]`. `CLAUDE.md` lists an open question about "the
  low-bit flag in the chunk length field, constant per stream"; this is a *high*-bit (or
  high-byte) flag and a different field, so it is a **lead, not an answer** — but the two readings
  should be reconciled by whoever picks that up, because "constant per stream" is exactly what
  `slot+76` is.
- The ring entry it fills is the one `sub_82B32550` claimed and `sub_82B332D0` recorded at
  `u8[slot+74]`: `entry = self + 16*that + 100`. It writes `+14` = the slot index, `+13` = **1**,
  `+8` = 0, `+4` = `u32[slot+40]`. That pins the ring's state machine end to end: **1** submitted
  (here), **2** finished (`sub_82B33F98`), **0** free (`sub_82B32480` clears it and
  `sub_82B32550` requires it). `+4` is the owner `sub_82B32480` hands to `sub_82EC1378` when the
  entry retires.
- Stores (8 outside this call's own frame, in order):
  - `stb r5,114(r9)` — `u8[entry+14] = index`, 1 byte
  - `stb r4,113(r9)` — `u8[entry+13] = 1`, 1 byte
  - `stw r6,108(r9)` — `u32[entry+8] = 0`, 4 bytes
  - `stw r8,104(r9)` — `u32[entry+4] = u32[slot+40]`, 4 bytes
  - `stw r9,8(r29)` — `u32[entry+8] = u32[record+32]`, 4 bytes, **mode path only, and it
    overwrites the zero two stores earlier**
  - `stb r3,12(r29)` — `u8[entry+12] = sub_82B3C870's request-slot index`, 1 byte
  - `stw r10,0(r26)` — `*counter += count`, 4 bytes
  - `stw r9,20(r30)` — `u32[slot+20] += count`, 4 bytes
  - the eight `stb` into `r1+80..83`, the `stwu` back chain and the `__savegprlr_24` spills are
    this call's own frame.
  `u32[record+32]` is **reloaded** after being stored into the entry rather than reused from the
  register; reproduced.
- `addi r10,r27,-8` computes the payload length (`length - 8`) and **nothing ever reads r10
  again** — the call below may clobber it. It is reproduced anyway, so the register file matches
  for a callee that happens not to write r10, and because it is the only place the payload length
  appears; a future reader should not take its absence for evidence that `+8` is not the payload
  boundary (`r4 = header + 8` is passed to the callee, which is the other half of that).
- Result: **r3**, the next header pointer, and `kReturnR3` is the honest mask. The add is
  `add r3,r27,r31` on the 64-bit entry value of r4, so a caller that passed a pointer with a
  nonzero high half gets a 64-bit sum back; `sub_82B33870` truncates it at `stw r3,48(r31)`.
- Gate 1 **fails at depth 1**: `sub_82B3C870` — already ported and labelled gate-1 — notifies its
  owner through a function pointer (`bctrl` at 0x82B3C8E4). It is called **unconditionally**, so
  no path is replayable. This is also why `sub_82B332D0` and `sub_82B28E60` fail at depth 2.
  Everything else about this function is harness-friendly: the write set is enumerable from entry
  state (one ring entry, two accumulator words, all addressed off `self`, the slot and the
  caller's pointer), there is no loop, and nothing is time-dependent.
- Unsure: what `u32[slot+56]`, `u32[slot+68]` and `u32[record+32]` are — they are only forwarded,
  never interpreted, on a path no known caller takes. `u8[entry+12]` holding the request-slot
  index is inferred from `sub_82B3C870`'s documented return ("the slot index used, or 0 when the
  slot was still busy"); nothing here checks it, which means a busy decoder ring is silently
  recorded as slot 0 and this function still reports success.
