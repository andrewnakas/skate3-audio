# sub_82B463A8

Leaf, 31 lines, no callees, no timebase, no lock. A command-ring handler (never called by `bl`;
its address is only ever stored as a record's `+0` handler pointer, e.g. the producer at
`skate3_recomp.11.cpp:59366`, which builds `{handler, object, index, float}` and advances the
ring by 16). 789,204 calls in the boot profile on `RwAudioCore Dac` — the hottest handler seen.

Argument: r3 = record `{+0 handler, +4 object, +8 index (u32), +12 value (f32)}`.
The object at `+4` is Player-like (the producer reads System from its `+8`); its `+0x10` holds
the base of an array of 8-byte slots `{marker u32, value f32}`. `+0x10` is unnamed in
`docs/rw_audio_structs.h`, so the port keeps a plain constant.

Stores, in order: `stfs f0 -> slots + (index<<3) + 4` (4 bytes, the float round-tripped
single→double→single), then `stw 0x7FF7FFF1 -> slots + (index<<3) + 0` (4 bytes). Returns 16
in r3 = the record size the drain advances by, so the mask is `kReturnR3`.

Window: one 8-byte span at `*(object+0x10) + (index<<3)`; every addend is loaded from entry
state before any store, so it is exact. Reads recorded: the 16-byte record and the 4-byte array
pointer. Windows() returns false if `object` or the slot base is 0 (the original would store
through a null-based address; it is skipped, not mis-windowed). Gates 1-4 all pass.

Unsure of: the meaning of the slot (`0x7FF7FFF1` is the same NaN payload
`docs/command-queue.md` sees `sub_82B28A00`'s query path stamp beside a 0.0/1.0 constant; here
it sits beside an arbitrary float). Reproduced, not interpreted. `index << 3` is 32-bit, as the
`rlwinm` — an index >= 2^29 would wrap identically in both.
