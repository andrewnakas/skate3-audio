# sub_82B27E20

One channel-bank low-pass stage on a 256-frame block. Args: r3 = the filter object, r4 = the
stream. Returns 1 in r3 on every path.

Object: +42 u8 channel count, +52 f32 cutoff numerator, +56 four state words per channel
(16 bytes, at most eight -- (184-56)/16), +184 five biquad coefficients, +204 f32 the cutoff the
coefficients were built from. Stream: +28/+32 the two buffer descriptors (ping-pong), +40 format;
format+12 f32 sample rate. Descriptor: +4 float* of channel 0, +14 u16 stride in floats.

Cutoff = float(float(obj+52 / rate) * [0x820B411C]). Two branches:

- **bypass** (`blt` false: cutoff >= [0x822F8E80], NaN included). If the *cached* cutoff at +204
  was itself below that ceiling, four state words per channel are zeroed (do-while, the count
  re-read from +42 each test). Then +204 = cutoff, return 1. **No descriptor swap** -- that is
  how the stage passes through: the caller keeps reading +28.
- **filter**. Clamp up to the floor [0x822F8E7C]; if the cutoff differs from +204, call
  sub_82B43CC0(r3 = obj+184, f1 = cutoff), which writes obj+184..203, then +204 = cutoff. Then
  per channel i: sub_82B43AF8(obj+56+16i, dst, src, obj+184, 256) with
  dst = buf(+32) + 4*stride*i, src = buf(+28) + 4*stride*i. Finally swap +28 and +32.

Stores: obj+56+16i .. +71+16i (4 x f32 per channel, both paths); obj+184..203 (20 B, via
sub_82B43CC0); obj+204 (4 B); stream+28 and stream+32 (4 B each); and per channel 1024 B at
dst (256 f32 written by sub_82B43AF8) plus its four state words, the same 16 B as above.

Callees, all through GuestCall: **sub_82B43CC0** (leaf apart from sin/cos 82F4DED0/82F4DFB0;
writes only r3+0..19 and its own frame) and **sub_82B43AF8** (writes r4..r4+1023 and r3+0..15;
saves/restores f20-f31 via __savefpr_20, touches no r26-r31). Neither allocates, locks, signals
or calls indirectly, and the census gives the whole closure gate1 = pass, depth 0. sub_82B43AF8's
scalar fallback sub_82B43978 is **unreachable from here** -- it is entered only when the count is
zero or not a multiple of eight, and the count is the literal 256 (`li r7,256`).

Window rationale: the union of both paths, all enumerable at entry. The channel count, both
descriptors and the format pointer are read before the first store and nothing this call writes
can change them (every store lands above obj+56, in the two descriptor *slots*, or in the output
block; a descriptor's own bytes are never written). Returns false when the object, the stream,
the format, either descriptor or either buffer base is null, or when the count exceeds eight
(a count that large would run the state array into the coefficients: a corrupted object, not a
case worth comparing). Budget at eight channels: 11 spans, 8352 bytes.

Two traps reproduced deliberately:

- `addi r3,r3,16` runs **after** the call, on whatever sub_82B43AF8 left in r3. It leaves r3
  untouched, so the walk works; the port reads `ctx.r3` rather than incrementing a local, so if
  a future port of sub_82B43AF8 ever writes r3 both sides change together.
- `mullw` then `rlwinm x,2,0,29` then `add` is a 64-bit add of two zero-extended halves. Kept in
  64 bits through to the GuestCall argument; only the store addresses truncate.

Unsure: the four constant-pool values were never read out of the image, so they are named by
position, not by value (kCutoffScale, kCutoffFloor, kCutoffCeiling). The loop re-reads the count
from obj+42 on every test; Windows assumes no store in the loop aliases obj+42, which holds as
long as the output block does not overlap the object.

Gate verdict: none fire -- callees replayable, write set enumerable from entry, no timebase, the
result is r3. STATUS pending, awaiting a shadow session.
