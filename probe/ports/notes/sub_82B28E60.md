# sub_82B28E60

- Role: the **PacketPlayer decode pump**. `void f(rw_player*)` -- no `li r3` on any path, so r3 is
  the last callee's result. 247 lifted lines, two direct callees (`sub_82B29018`, `sub_82B28D08`),
  **no `bctrl` of its own**. 1,681 calls per boot on `RwAudioCore Dac`.
- Object: `rw_player` (docs/rw_audio_structs.h). Fields used, with two this function pins down:
  `+12` the registration record (its `+71` kind byte -- `2` is what `sub_82B49280` writes when the
  registration failed, and it aborts this call), `+0x54` the twenty stride-12 entries
  (`+0x00` a word, `+0x08` the decoder slot index, `+0x09` the discriminator), `+0x150` decoder,
  `+0x154` sample rate **read as an f32** (`lfs`), `+0x15E` state, `+0x164` an s32 sample counter,
  `+0x173` (`stop_field173`) **the index of the current table entry** -- which is why EVENT_STOP
  clears it -- and `+0x30` an **8-byte double** holding the playback position, neither of the last
  two named in the struct today.
- Flow:
  1. `u8[[self+12] + 71] == 2` -> return, nothing touched.
  2. Twenty passes (`mtctr 20` / `bdnz`), stride 12, over the table at `+0x54`. An entry whose
     discriminator is exactly 2 is retired when its decoder slot is finished:
     `slot = u8[entry+8]`, `decoder = [self+0x150]` (**not** null-checked -- a null decoder reads
     its table offset from address 36), `ring = decoder + [decoder+36] + slot*24`;
     retire if `(s32)[ring+12] == 0`, or if `[ring+12] - start == 0` on the low word, where
     `start` is `[decoder+28]` when `slot == u8[decoder+49]` and `[ring+8]` otherwise. Retiring
     writes `stb 0 -> entry+9` then `stw 0 -> entry+0`, in that order.
  3. `active = state != 4 && state != 0` (`cmpwi 4` / `cmpwi 0` / `li 1` / `clrlwi 24`; the byte is
     0 or 1 before the mask, so the mask is a no-op). Not active: `stfd [0x822F8700] -> self+0x30`
     and return.
  4. Active: `self+0x30 = double(extsw(s32[self+0x164])) / double(f32[self+0x154])` -- `fdiv`, a
     full **double** divide, through a `std`/`lfd`/`fcfid` round trip at frame+80.
  5. Then spin: re-read the state; stop if not active; stop if the entry the cursor at `+0x173`
     names has a non-zero discriminator. In state 1, call `sub_82B29018(self)`, stop if its **low
     byte** is zero, else `stb 2 -> +0x15E`. Re-read the state; if it is not 2, go round again.
     Re-read the cursor and its entry (both may have moved) and go round again if the entry is now
     busy. Otherwise `sub_82B28D08(self, 0)` and loop while its low byte is non-zero.
- Stores: `stb 0 -> entry+9` and `stw 0 -> entry+0` inside the retire loop (up to twenty of each),
  `stfd -> self+0x30` on exactly one of the two position paths, `std -> frame+80` (own frame), and
  `stb 2 -> self+0x15E` once per successful codec start.
- Result mask: **honest mask is none** -- nothing is returned and no caller can read a defined
  value. Declared `kReturnR3` because a false `Windows()` with `kReturnNone` trips lint check 5.
- Gate: **1, fail**. It owns no indirect call, but the census finds `sub_82B3C870`'s virtual notify
  (`bctrl` 0x82B3C8E4) at **depth 2** through these callees, and `sub_82B29018` is itself
  non-replayable one level down: docs/shadow-harness.md records that it takes a critical section
  and makes two indirect calls, and docs/PLAN.md lists it as a closure parameter for the Rust port
  rather than a port. The loop calls both callees repeatedly, so no entry-state prediction avoids
  them. `Windows()` returns false. Gate 2 would also fail: the number of decode requests, and
  therefore of `sub_82B28D08`'s writes, is decided by that callee's own return value.
  Gate 3 passes (no `mftb`) in this body, though `sub_82B28D08` was not screened for one.
- Unsure:
  - `+0x30` as a double is certain from the `stfd`; that it is a *time* is inference from
    `samples / rate`. The pool double at `0x822F8700` was not read out of the image dump; it is
    almost certainly 0.0, and a negative or sentinel value would change the reading.
  - `kSlotStart`/`kSlotEnd` (+8/+12 of the 24-byte ring entry) and `kDecoderCursor` (+28): the test
    is "end is zero, or end minus start is zero". Which is the producer and which the consumer is
    not established, so the names are positional only.
  - Why `u8[decoder+49]` substitutes `[decoder+28]` for the slot's own `+8`. It reads like the
    ring's live write cursor being kept outside the entry while that entry is the one being
    filled, but nothing here proves it.
  - `+0x164` is signed (`extsw`) and outside the struct as written. Whether it is a sample count or
    a byte count depends on `+0x154`'s units, which this function only divides by.
