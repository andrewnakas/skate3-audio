# sub_82B32870

- Role: `void f(record*)` — stop/tear down a voice record. It calls `sub_82B32328(record)`, which
  resets that record's `+432..+477`; then, **only when the state byte at `+476` reads exactly 1**,
  it clears `u32[+24]` and `u8[+43]` and calls `sub_82B489D0(record->+8, record+72)` to hand the
  node at `+72` back to the owner's pool; then, when `u32[+440]` is nonzero, it releases that
  pointer through the owner's allocator: `u32[u32[u32[record->+8 + 36] + 0] + 12](allocator,
  held, 0)`. 71 lifted lines, two direct callees, one own indirect call, no imports, no timebase,
  no lock. 1,907 boot calls on `RwAudioCore Dac` (tier D).
- Argument: r3 = the record. r4-r10 are not read on entry.
- The owner/allocator pair — `record->+8` is the owner, `owner+36` the allocator, allocator
  vtable slot `+12` the free entry — is the **same pair** `sub_82B34D60` uses (reached from
  `sub_82B34B50` in this batch), which is a second independent reading of it. `+36` (0x24) falls
  inside `rw_system`'s undocumented `_pad24`, so no name was borrowed.
- Stores (2 to the record, 3 to this call's own frame):
  - `stw r11,24(r31)` — `u32[record+24] = 0`, 4 bytes, state==1 path only
  - `stb r11,43(r31)` — `u8[record+43] = 0`, 1 byte, state==1 path only
  - the `-8(r1)` link, `-16(r1)` r31 save and the `stwu` back chain are the frame; never windowed,
    but the frame is reproduced because all three callees run on it.
  The `+476` load is a genuine **reload after** `sub_82B32328`, which writes `+477` and neighbours
  — hoisting it above the call would be wrong, so the port loads it where the original does.
- Result: **none.** There is no `li r3,...` on any path; r3 is left as whatever the last call
  returned, so the function is void by construction. The macro line still carries `kReturnR3`,
  because a gate-labelled port with a false `Windows()` and `kReturnNone` trips lint check 5 (a
  vacuous comparison) — and the mask is never read, since the macro does not arm the shadow
  branch for a gate label. A comparable version would declare `kReturnNone` plus the write set
  below.
- Gate 1 **fails** twice:
  1. depth 0, this function's own `bctrl` at **0x82B328D0** — a heap free through a vtable slot,
     unreplayable on rewound memory, taken whenever `u32[+440]` is nonzero;
  2. depth 1, `sub_82B32328` (skate3_recomp.67.cpp:49756) reaches an indirect call through
     `sub_82B33F98`, and it is called unconditionally on the single entry path.
  So there is no path on which this is replayable, and `Windows()` returns false.
- The write set I WOULD have declared if it were comparable: `spec.write(r3 + 24, 4)`,
  `spec.write(r3 + 43, 1)`, union `sub_82B32328`'s `+432..+478` block (declarable as
  `spec.write(r3 + 432, 46)`) and `sub_82B489D0`'s writes into `record->+8 + 112 ..` (a
  32-byte-stride slot chosen by `u8[node+20]`, plus three words in the node itself); reads
  `{r3 + 8, 4}`, `{r3 + 440, 4}`, `{r3 + 476, 1}`, `{r3 + 72, 24}`. All of that is enumerable
  from entry state — gate 1 is the only blocker, not gate 2.
- Unsure: whether `+24`/`+43` are a cursor and a flag or something else. They are only ever
  cleared here, so the rewrite is safe, but the reading is a guess and is labelled as one.
  `sub_82B489D0`'s `+112` region looks like a fixed array of pool slots indexed by the node's
  `u8[+20]` class (`rlwinm r10,r10,5,0,26` — stride 32); that was read once and is not confirmed.
