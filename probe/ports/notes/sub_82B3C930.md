# sub_82B3C930

**This is the canonical gate-1 case in this project.** `docs/shadow-harness.md` already names
it: `EVENT_STOP` (`sub_82B28C18`) calls it whenever a decoder is live, "whose four indirect
calls release and unregister the voice", and replaying that against rewound memory would tear
down an already-released object -- no memory window can undo a release. It is the reason
`EVENT_STOP` has **no comparable path**: stopping playback is exactly when a decoder exists,
so the measured session produced 0 comparable calls and 1 skipped. `docs/PLAN.md` lists it as
a closure parameter, not a port, for the same reason.

Ninety-six lifted lines, of which twelve are frame. Four `bctrl`s, no direct callees, no
imports.

What it does, in order: `r3` is the decoder object.
1. `12(r3)` is a raw function pointer -- a stop/flush hook. If non-zero, call it with `r3`
   unchanged and nothing else set up.
2. `16(r3)` is a held voice. If non-zero, release it: `r3` = the table owner at
   `36(*0x8307762C)`, `r4` = the voice, `r5` = 0, target = `(*(owner+0))+12`.
3. Unregister itself: `r3` = self, `r4` = 0, target = self's own vtable slot `+4`.
4. Release itself through the same `+12` release slot, `r4` = self, `r5` = 0.

The `(owner+36) -> (+0) -> (+12)` chain is the same release entry `sub_82B34D60`
tail-branches to, and `0x8307762C` is the cell `port_82B219E8` already names `kStatsOwner`
(computed as `((-31993 & 0xFFFF) << 16) + 30252`, not read by eye).

One ordering detail preserved: the pointer at `0x8307762C` is loaded into the callee-saved
`r30` *before* step 3's call, not re-read after it -- the compiler hoisted it past the call
because the volatiles die there. The native body keeps that order; re-reading the cell after
the unregister would be a different program if the unregister ever rewrites it.

Stores: **none outside its own frame.** The census's four entries are `stw r12,-8(r1)`, two
`std`s of r30/r31 and the `stwu`, all excluded by the brief. Everything this function changes
is changed by its four indirect targets.

Gate verdict: **gate 1**, at depth 0, four times over. Two of the four calls are
unconditional, so no entry-state predicate carves out a comparable path; and the last one is
a self-release, which means a replay would free the same object twice. This is the strongest
form of the gate -- not "the target is unknown" but "the effect is irreversible".

Write set that would have been declared if it were comparable: nothing of its own. It would
be the union of four indirect targets' write sets, none of which is knowable from entry state
-- the targets are vtable slots read during the call, and the release path reaches the
allocator. So gate 2 holds as well, at one level down. Result mask: r3, which on exit is
whatever the final release call leaves; the function computes no result of its own, and
`EVENT_STOP` ignores it.

Uncertain: whether `12(r3)` is a plain function pointer or a one-entry table -- the lifted
form calls it directly (`mtctr r11` off the loaded word, no second load), so it is a raw
pointer, but nothing says what signature it expects beyond `r3` = self. Also unverified that
`kSelfSlotUnregister` (+4) is an unregister rather than a destructor-with-flag: the `r4 = 0`
argument is the shape of an Itanium-ABI-style "do not free" flag, which would make step 4's
release the actual free. The observable behaviour is the same either way.
