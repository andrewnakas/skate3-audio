# sub_82B489D0

- Role: `void f(rw_system*, rw_instance*)` — detach a scheduler instance. Either unlinks the
  instance's node from its bucket now, or (when the instance is the one the tick is running)
  parks the removal for `sub_82B48A50` to finish; then clears the instance's elapsed word and
  marks it bucket 3. 71 lifted lines, one direct callee, no imports, no indirect call, no lock,
  no timebase. 1,967 boot calls.
- Arguments: r3 = the System, r4 = the instance. The scheduler is `r3 + 0x70`
  (`docs/rw_audio_structs.h`), so `r3+180` is `rw_scheduler.current_node` (+0x44), `r3+184` is the
  undocumented `_pad48` word and `r3+188` is `node_removed` (+0x4C). `sub_82B48A50`'s note has the
  other half of this protocol: on the removed path it hands `scheduler + u32[scheduler+0x48]*32`
  to `sub_82B39690` — this function is what writes that index and that node.
- Three paths, all selected from entry state (both tests load before the first store):
  - `r4 == u32[scheduler+0x44]`: `u32[scheduler+72] = u8[instance+20]` (the bucket index,
    zero-extended); then `node = u32[instance+0]`, `u32[instance+0] = 0`, `u32[node+8] = 0`,
    `u32[scheduler+76] = node`. **No bucket test on this path** — the running instance is parked
    whatever its bucket byte is, including 3.
  - otherwise and `u8[instance+20] != 3`: `node = u32[instance+0]`, `u32[instance+0] = 0`,
    `u32[node+8] = 0`, then `sub_82B39690(scheduler + 32*bucket, node)`.
  - otherwise: nothing.
  Tail on all three: `u32[instance+16] = 0`, `u8[instance+20] = 3`.
- Stores: `scheduler+72` and `scheduler+76` (4 B each, adjacent — one 8 B span); `instance+0`
  (4 B); `node+8` (4 B); `instance+16` (4 B) and `instance+20` (1 B, adjacent — one 5 B span);
  plus `sub_82B39690`'s seven, re-derived in `Windows()` from its lifted form: one bucket head
  when the node is that head, `next+0` and `prev+4` when non-null, the node's two link words,
  `free_head+4` when non-null, the bucket's free head and its count. The `stw r12,-8(r1)` and
  `stwu r1,-96(r1)` are this call's own frame and are not reproduced: `sub_82B39690` is a leaf
  that touches no stack at all, so unlike `sub_82B43CC0` there is nothing below r1 to protect.
- `+0` on the instance: `docs/rw_audio_structs.h` labels it `descriptor -> rw_plugin_desc`, but
  what both this function and `sub_82B39690` do with the pointed-at object is read its `+0`/`+4`
  links, its `+12` byte and clear its `+8` back pointer to the instance — i.e. it is the node.
  The port names it `kInstanceNode` for that reason; the struct header is probably mislabelled
  here (same kind of correction `sub_82B48A50`'s note makes for `+0x44`).
- Window rationale: the path is predicted, so the declared set is the exact one, not a union.
  Returns false when the System or the instance is null; when the node pointer is null (the
  original would store to guest address 8 and hand null to `sub_82B39690`); when the store at
  `scheduler+72` would land on `u32[instance+0]`, which is loaded *after* it (that is the gate-2
  case on the parked path); when `sub_82B39690`'s free-head field lives inside the node's two
  link words (its own gate-2 guard, copied); and when either store this function makes before the
  call overlaps any of the six fields the callee addresses from entry state. Budget on the
  unlink path: at most 10 write spans, 45 bytes.
- `sub_82B39690` goes through `GuestCall`, not `__imp__`: it is itself a verified port, the
  census gives the closure `gate1 = pass, depth 0`, and it neither allocates, locks, signals nor
  calls indirectly — it only rewrites list links.
- Result mask `kReturnR3`. The function is void by use, but r3 is reproducible on every path and
  a free extra check: untouched on the parked and already-detached paths, and
  `(bucket*32) + (int64(r3) + 112)` on the unlink path, formed by a **64-bit** `add` on
  `addi r11,r3,112`, so the high half of the entry r3 is carried through deliberately.
- Unsure: the package header attributes the calls to `MoviePlayer2 De` while the census JSON in
  the same package says `RwAudioCore Dac` — two different sessions, and the .inc header carries
  the package's own line. Either way the object graph is the same. Also unverified: whether
  bucket values above 2 ever occur; the port reproduces `bucket*32` for any byte value rather
  than bounding it, because the original does, and `Windows()` derives the manager address the
  same way, so a wild bucket byte is declared rather than guarded.
- Gate verdict: none fire on the compared paths — callee replayable, write set enumerable from
  entry, no timebase, r3 observable. STATUS pending: written, never compared.
