# sub_82B1D700

Leaf, 83 lines, no stores, no callees. Argument r3 = an operand block: u8 `count` at +0, u32
`cap` at +4, u32 `words[count]` at +8. Result r3 = min(sum(words), cap) where the compare is
signed 32-bit on the low words and the sum is a 64-bit accumulation of zero-extended u32
loads (can carry past bit 31; r3 keeps all 64 bits when not clamped, `cap` zero-extended
when clamped). Bug for bug: with count 0 or 1 the result is `words[0]` alone -- count 0
still reads +8. The pair loop (`bdnz`, ctr = ((count-3)>>1)+1) takes words[1..2P]; an odd
count adds the trailing word `words[2P+1]` via `lwzx` at `((2P+3)<<2) + block`.

Caller: not called directly anywhere in the lifted code. It is slot 30 (+120) of the
function table at guest 0x82FD3600 (found in the decrypted image dump, one hit), which
`sub_82B1E290` (TU 67) indexes by a record's opcode byte and calls with r3 = the operand
block; that interpreter then stores the returned r3 (`stwx r3,r9,r31`) for every pair whose
source index is -1, so r3 is consumed: `kReturnR3`. The other reference, `sub_82B1DF50`,
only patches `table[op] - site - 4` into records (a relocation), not a call. The sibling
verified port `sub_82B1D198` is slot 36 of the same table.

Windows: none. Reads `{r3, 8 + 4*max(count,1)}` for replay. Callee-saved registers untouched;
cr6/ctr are not compared. Gates 1-4 clean. Counts: boot 667,728 calls on RwAudioCore Dac.
Unsure: what the table's opcode set represents (an audio parameter/expression evaluator by
shape); irrelevant to exactness.
