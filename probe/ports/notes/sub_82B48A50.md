# sub_82B48A50

- Role: `void f(rw_scheduler*, uint32_t bucket)` — the scheduler tick. It takes the node list at
  `scheduler + (bucket<<5) + 0x10` and, for each node: publishes the node's instance at
  `u32[scheduler+0x44]`, clears `u32[scheduler+0x4C]`, calls `u32[instance+4](u32[instance+8])`
  with `f32[scheduler+0x40]` in **f1**, then either writes the `mftb` delta into
  `u32[instance+0x10]` (when `u8[descriptor+12]` is nonzero) or zeroes it; if the node set the
  removed flag while it ran, it hands `scheduler + u32[scheduler+0x48]*32` to `sub_82B39690` and
  clears the flag. The successor is read **before** the process fn runs, so a node that unlinks
  itself is still followed to its entry-time `next`. 128 lifted lines, two direct callees, one own
  indirect call, no imports, no lock. **37,370 boot calls** on `RwAudioCore Dac` (tier D).
- Arguments: r3 = the scheduler (System + 0x70), r4 = the bucket index. `docs/rw_audio_structs.h`
  says the drain ticks buckets 0 and 1 each frame, so r4 is small in practice — but the port
  writes the `rlwinm r11,r4,5,0,26` out as `(r4 << 5) & 0xFFFFFFE0` rather than `r4 * 32`,
  because the operand is a full word and the rotate really does discard bits above 0x07FFFFFF.
- One correction to `docs/rw_audio_structs.h`: `+0x44` is labelled `current_node`, but what this
  function stores there is `u32[node+8]` — the **instance**, not the node (and 0 when the node has
  no instance). The port names it `kRunning` for that reason. Everything else in the struct checks
  out field for field: buckets at `+0x10` stride `0x20`, `delta_time` at `+0x40`, `node_removed`
  at `+0x4C`, `rw_node.next` at `+0`, `rw_node.instance` at `+8`, `rw_instance.process` at `+4`,
  `.context` at `+8`, `.elapsed` at `+0x10`. `+0x48` (the index scaled for `sub_82B39690`) falls
  in the struct's `_pad48` and is still undocumented.
- Stores (6, all outside this call's frame, up to 5 per node):
  - `stw r31,68(r30)` — the running instance, 4 bytes, before the process call
  - `stw r29,76(r30)` — `node_removed = 0`, 4 bytes, before the process call
  - `stw r29,68(r30)` — the running instance back to 0, 4 bytes, after it
  - `stw r11,16(r31)` **or** `stw r29,16(r31)` — `instance->elapsed`, 4 bytes, exactly one of the
    two on the not-removed path
  - `stw r29,76(r30)` — `node_removed = 0` again, 4 bytes, only on the removed path
  - the `stwu` back chain is this call's own frame; never windowed.
  `u32[scheduler+76]` is reloaded after the process call (that is the whole point of clearing it
  before), and the instance's descriptor is reloaded from `u32[instance+0]` after it too.
- Two branches are folded in the port, both provably dead rather than simplified away:
  `cmpwi` then `cmplwi` on the same bucket head (the second test cannot change the outcome), and
  the `r11`/`r29` arms that both leave `r31` equal to `u32[node+8]`. A node with a null instance
  therefore dereferences guest address 0; that is reproduced, not guarded.
- Result: **none** honestly — no `li r3,...` on any path, so r3 is the scheduler when the bucket
  is empty and the last callee's result otherwise. The macro line carries `kReturnR3` because a
  gate-labelled port with a false `Windows()` and `kReturnNone` trips lint check 5; the mask is
  never read for a gate label. A comparable version would declare `kReturnNone`.
- Gate 1 **fails at depth 0**: this function's own `bctrl` at **0x82B48AC0**, through
  `u32[instance+4]` — arbitrary plug-in code, whose write set is the whole audio engine. It is
  unconditional for every node in the bucket. `docs/shadow-harness.md` already records this
  function as a gate-1 candidate from the original Phase 2 screening (the table row
  "`sub_82B48A50`, `sub_82B48530`, `sub_82B48440` | gate 1 — indirect calls"); this port is the
  first time its body has been written out.
- It **also fails gate 3**, twice per node, through `sub_82B1F7E8` (`mftb`) — the same function
  `port_82B1F7E8` labels gate 3 on its own. So even a hypothetical harness that could replay the
  process fn would still compare `u32[instance+0x10]` against a different timebase delta. Two
  independent gates, and the census's `timebase: 0` is about *direct* `mftb` only — worth
  remembering when reading the screen.
- The write set I WOULD have declared: per node `spec.write(scheduler + 68, 4)`,
  `spec.write(scheduler + 76, 4)`, `spec.write(instance + 16, 4)` — three spans, 12 bytes, and the
  node walk is bounded by the bucket length so the budget is fine — plus, on the removed path,
  `sub_82B39690`'s write set, and on every path the process fn's, which is the blocker. Reads
  `{bucket + 16, 4}`, `{scheduler + 64, 16}` (`+64`, `+68`, `+72`, `+76`), `{node, 12}` and
  `{instance, 20}` per node, `{descriptor + 12, 1}`.
- Unsure: what `u32[scheduler+0x48]` indexes. It is scaled by 32 exactly like the bucket index, so
  `sub_82B39690` is presumably being handed *a bucket* — the one the removed node belonged to —
  but that function was not read, and the index is written by someone else (nothing here writes
  `+0x48`).
