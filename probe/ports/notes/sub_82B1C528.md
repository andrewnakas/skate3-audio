# sub_82B1C528

Non-leaf, 64 lines, 164,069 calls in the verifying boot session on `RwAudioCore Dac` (196,476 in
the screening census). Compared clean, promoted to `kPortVerified`. One callee,
`sub_82B1F360`, taking no arguments -- already a verified port: a six-word cascading counter at the
fixed global `0x830775F0` (`lis r11,-31993 ; addi r11,r11,30192`, computed as
`((imm & 0xFFFF) << 16) + offset`, not read off). It is the only state the draw depends on: no
timebase, no lock, no allocation, no indirect call, closure size 1, census gate-1 verdict pass.

No caller appears in the lifted sources (`grep "sub_82B1C528(ctx, base)"` over `generated/` finds
only its own definition), so like `sub_82B1C598` it is reached through a function pointer. Both
exits leave a value in r3, so the mask is `kReturnR3` -- and r3 is compared as all 64 bits, which
matters here (see below).

Argument: r3 = the object. Nothing in `docs/rw_audio_structs.h` names it. Fields: `u32 +0` a base
added to the remainder; `u32 +4` the modulus; `u32 +8` the cached result, the only word written;
`u32 +12` an enable -- zero means hand back `+8` with no draw and no store.

Behaviour: if `s32[+12] == 0`, return the zero-extended `u32[+8]` and stop. Otherwise draw the
counter and store `u32[+0] + draw % u32[+4]` into `+8`, returning it. A ranged random value with a
cached last result, which is what the arithmetic says; whether it is a pitch, a volume or a delay
is not established.

Stores: one, `stw` 4 bytes at `+8`, off the entry pointer. Plus `sub_82B1F360`'s whole 24-byte
counter, all six words of which it writes on every call.

The 64-bit trap is live here, twice over. `divwu` divides only the LOW word of the counter result,
but `subf r11,r8,r3` subtracts the `mullw` product from the FULL 64-bit r3, so the remainder carries
the counter word's high half with it; and `add r3,r11,r10` sums that with a zero-extended `+0`, so a
carry lands in bit 32. r3 keeps all 64 bits and only the `stw` truncates. `mullw` is itself a 64-bit
product of two sign-extended words. Every intermediate in the port is `uint64_t`/`int64_t` and the
casts are at the store, not before it.

`twllei r11,0` (modulus zero) is reproduced. `ppc_trap(type 0)` in `generated/skate3_init.h` only
logs a warning and returns, so it is replayable, and -- unlike `sub_82B1C598`, which declines that
case -- the store address here does not depend on the range, so a zero modulus stays fully inside
the declared window and is compared rather than skipped. The lifted line's `r11.u32 < 0u` half is
dead and is dropped: clang rejects a tautological unsigned compare in `src/` even though it passes
in `generated/`.

Own frame (`stw r12,-8(r1)`, `std r31,-16(r1)`, `stwu r1,-96(r1)`) is not reproduced and not
windowed: `sub_82B1F360` is a leaf that touches no stack at all, so nothing depends on the frame
existing. r31 is the only callee-saved register the original uses and it round-trips through its own
spill; the port does not touch it.

Window: two spans, `{+8, 4}` and `{0x830775F0, 24}`. The early path is predicted exactly -- `+12`
is read before the branch and before the call, so entry state settles which path runs, and that path
writes nothing. `Windows()` returns false on exactly one condition: an object whose 16-byte header
overlaps the counter global, because `+0` and `+4` are read *after* the counter has advanced and
would then not derive from entry state.

Gates: 1 pass. 2 pass (the census flagged one store gate2_suspect for a derived base; the base is
r31, which is the entry r3). 3 pass -- the draw is a deterministic counter, not `mftb`. 4 pass.

Unsure: (a) the meaning of the four fields is read off the arithmetic only; no symbol names them.
(b) Whether `+12` is a boolean or a small enum is unread -- the original only tests it against zero,
and so does the port.
