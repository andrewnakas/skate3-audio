# sub_82B34B50

- Role: `f(record*)` — retire one record. If the flag byte at `+164` is nonzero, unlink the
  record's intrusive node at `+44` from a global registry list whose head is the word at
  `0x830BDEB8`; then tail-call `sub_82B34D60(record+52, record->+8)`, which detaches that
  sub-object's children and releases its held pointer. 55 lifted lines, one callee, no imports,
  no own indirect call, no timebase, no lock. 244 boot calls on `RwAudioCore Dac` (tier D).
- Argument: r3 = the record. r4-r10 are not read on entry.
- Constant: `kRegistryHead = ((-31988 & 0xFFFF) << 16) + (-8520) = 0x830C0000 - 0x2148 =
  **0x830BDEB8**`. Computed, not read off by eye. The lifted `lis` leaves `s64 = -2096365568`,
  which is the sign extension of `0x830C0000` — the check that the immediate was read right.
- Node layout, read off the code rather than assumed: the head-equal path takes `[node+0]` as the
  new head, so **next is at +0 and prev at +4**. The identical unlink appears again inside
  `sub_82B34D60` (over a head at `owner+4`), which is a second reading of the same layout.
- Stores (3 `stw`, 4 bytes each, all on the linked path):
  - `0x830BDEB8` = `u32[node+0]`, only when `node == head`
  - `u32[prev+0]` = `u32[node+0]`, only when `s32[node+4] != 0`
  - `u32[next+4]` = `u32[node+4]`, only when `s32[node+0] != 0`
  Both node words are **reloaded** for the second and third stores; the first store aliases
  `node->next` on a one- or two-element list, so the reloads are load-bearing and reproduced.
- Result: r3 is inherited from the tail call to `sub_82B34D60`. Mask `kReturnR3`.
- Gate 1 **fails**: `sub_82B34D60` (skate3_recomp.67.cpp:55900, 92 lines, itself a leaf apart
  from this) ends in `bctr` at **0x82B34E00**, dispatching `u32[u32[u32[owner+36]+0]+12]` with
  r3 = the allocator, r4 = the held pointer, r5 = 0 — the allocator's free entry. A free cannot
  be replayed on rewound memory, and it is on every path where the held pointer is nonzero, so
  the whole function is unreplayable. Gates 2, 3 and 4 are not the blocker: no timebase, no lock,
  r3 observable.
- The write set I WOULD have declared if it were comparable: `{0x830BDEB8, 4}` plus
  `{REX_LOAD_U32(r3+44+4), 4}` (prev->next) and `{REX_LOAD_U32(r3+44)+4, 4}` (next->prev), each
  predicted from entry state and skipped when the pointer is zero, union
  `sub_82B34D60`'s own set; reads `{r3+44, 8}`, `{r3+164, 1}`, `{r3+8, 4}`, `{0x830BDEB8, 4}`.
  All three writes are enumerable from entry — it is only gate 1 that stops this one.
- Unsure: whether `+52` is a distinct sub-object or the record simply continues there;
  `sub_82B34D60` treats it as `{?, list_head at +4, held at +8}`, which is consistent with either.
  Nothing turns on it for the rewrite.
