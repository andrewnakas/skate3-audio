# sub_82B31D90 — unpack a packed 64-bit stream header

Arguments: r3 = byte stream, r4 = output record. Void (r3 is left holding the last field read,
which no caller has been shown to use, so the result mask is `kReturnNone`).

Body: if the first byte is 72 ('H') the stream pointer is advanced four bytes. A two-word bit
reader `{stream, cursor=0}` is built at sp+80 and `sub_82B26B70` is called six times through it,
reading 4, 4, 6, 18, 3 and 29 bits — 64 bits, i.e. exactly eight header bytes. The first and
fifth results are discarded; the others are stored.

Stores, in the original's order:
- `stw r3,12(r31)` — out+12, 4 bytes (second 4-bit field)
- `stb r10,0(r31)` — out+0, 1 byte, the 6-bit field **plus one**
- `stw r3,4(r31)`  — out+4, 4 bytes (18-bit field)
- `stw r3,8(r31)`  — out+8, 4 bytes (29-bit field)

Windows: `out+0` (1) and `out+4` (12). `sub_82B26B70`'s only store is the bit cursor at
reader+4, which is this function's own frame (sp+84): not windowed, not reproduced. The stream
bytes are read-only. Reads declared: the tag word at `stream`, and the eight header bytes from
the post-skip base — the skip decision is entry state, so the read set is exact.

Mirrors `recomp/src/audio_ports/sub_82B26B70.inc` for the reader layout and for the claim that
its write set is one word inside our frame; a change to that port's write set requires a change
here.

The `stwu r1,-112(r1)` frame move is REPRODUCED, because the reader sp+80 is passed to a callee
as a guest pointer; without the move it lands in the caller's frame, outside every window.
r31 is saved and restored, as the original does, because `sub_82B26B70` uses it and the harness
compares r13-r31.

Gates: 1 pass (the one callee is a pure bit reader, no allocation, lock, indirect call or
timebase); 2 pass (write set is four fixed offsets off r4); 3 pass; 4 pass (the writes are the
observable). STATUS pending — not yet compared.

Unsure: what the four fields mean. The widths suggest a codec/format nibble at +12, a
channel-or-block count at +0 (n+1), a rate at +4 and a sample or frame count at +8, but nothing
in the function confirms it and `docs/rw_audio_structs.h` does not name this record, so the
constants are left as widths.
