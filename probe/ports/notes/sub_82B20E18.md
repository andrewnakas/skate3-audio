# sub_82B20E18

Leaf, 143 lines, **1 call in the boot profile** -- verification here will be thin whatever the
divergence figure says.

Applies a rising ramp to an interleaved float block at r3. The channel count is not an argument:
it is the global byte at 0x8306705D, and the block is `channels * 512` bytes, which is 128 frames
of `channels` samples. Each frame is multiplied by `frame_index * scale`, where `frame_index`
starts at the 0.0f pool cell and increases by the 1.0f cell each frame, and `scale` comes from
0x820300D4. Within a frame the samples are scaled four at a time and then one at a time, with
the gain recomputed identically in both loops.

Write set: one contiguous span `{r3, channels * 512}`, read back in the same call. The count is
loaded once before the loop and never reloaded, so the span cannot change mid-call -- unusually
clean for a loop this shape. `Windows()` returns false when the span exceeds the 32 KB budget
(any count above 63) or would wrap, so a six- or eight-channel block is comparable and a
pathological one is skipped rather than mis-windowed.

`kReturnR3`: r3 ends at the block's end pointer, or unchanged when the count is zero.

The `stfsu` in each loop both stores and advances the pointer; the port advances an explicit
cursor instead, which is the same addresses in the same order.
